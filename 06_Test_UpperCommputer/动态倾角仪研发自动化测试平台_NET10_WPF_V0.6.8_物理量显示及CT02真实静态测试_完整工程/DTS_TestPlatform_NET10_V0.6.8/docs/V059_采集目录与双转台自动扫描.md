# V0.5.9 使用说明：独立 IMU 采集目录 + 双转台独立自动扫描

## 一、三个目录完全独立

1. 主界面顶部 **报告保存到**：用于 CT-05 等自动化测试的测试结果、报告、检查点。沿用 `_saveRoot`，本版没有改变原有测试模块和报告的路径逻辑。
2. 主界面顶部 **标定文件夹**：用于递归寻找与当前真实 UID 对应的 ACC/Gyro 常温及全温 JSON，不是写入目录。
3. 右侧 **IMU / 采集 / 补偿** 页签中的 **采集数据保存到 → 选择路径…**：用于单击“开始采集”的独立数据归档。自动记录 `imu_selected.csv` 和不可修改的原始备份 `imu_raw.csv`。此路径不再继承报告目录。

采集数据举例：

```
D:\IMU_原始与补偿采集\
  DTS672516_002900593252501720323350\
    20261103_120000_123_RAW_ACQUISITION\
       imu_selected.csv
       imu_raw.csv
       manifest.json
       calibration_snapshots\   (选择并成功验证标定时才有)
```

采集目录保存在当前 Windows 用户的 `%LOCALAPPDATA%\DTS_TestPlatform\capture_root.txt`，重新打开软件自动恢复；没有历史选择时，默认为当前用户“文档”下的 `DTS_IMU_Captures`。报告目录继续用 `output_root.txt`，两者不可选择同一个文件夹。路径必须有写入权限。

> “采集”是 IMU 页签的手动/定时记录按钮；CT-05 等独立测试仍然使用全局报告目录。现有“显示什么模式就记录什么模式”的主文件 `imu_selected.csv` 逻辑保持不变，原始备份同时保留。

## 二、自动识别 2TD-600

- 进入 **2TD-600 双轴转台** 页签 → 点击 **自动扫描**。
- 扫描从 Windows 的可用 COM 列表查找空闲端口，主动避开已连接 IMU 的 COM 和其他已连接设备的 COM。
- 针对 115200、921600bps **只监听**符合已有协议校验条件的状态帧，过程中不发送使能、位置或运动指令。
- 只有一个有效候选端口时自动填入 COM/波特率。然后人工点击 **连接 2TD**，读实时状态。
- 如有多个候选，只显示候选列表，要求核对设备线缆后再选；未收到有效帧不猜测端口。特别注意：如果该型号不主动持续发送状态帧，仅靠被动监听可能无法发现；这需要进一步验证厂商的状态查询协议/反馈模式。

## 三、自动识别 2FDT600WK 温控双轴转台

- 进入 **2FDT600WK 温控转台** 页签 → 点击 **自动扫描**。
- 跳过所有已连接的设备端口；其余候选端口使用原厂家 DLL 提供的 `GetStateInfo(port,axis,...)` **读取状态**，不调用位置/使能/停止命令。
- 内外轴分别要求获得有效且重复的响应。能唯一确认 **两个不同 COM 口**时自动填写。否则提示候选及冲突，不擅自绑定错误轴。
- 操作人员核对实际接线和控制器状态后再点击 **连接温控转台**。

## 四、运行安全边界

- 自动扫描不等于自动连接，更不等于自动运动。
- 连接串口并不证明两个设备的机械状态安全；执行相对运动前仍需核实限位、夹具、物理急停、人员与电缆余量。
- 如果外部厂家软件占用端口，扫描可能失败；请关闭占用后重试。
- 正在执行采集或测试时禁用设备扫描；两种专用扫描在同一时间不能并发。
- 本版以历史已有的真实通信与厂家 DLL 调用为基础编写，尚未经过此工作环境中的 Windows 编译和实体转台联调。请优先执行“空载状态读取验证”，再由现场人员监督小角度测试。

## 五、Windows 更新验证

1. 建议先备份原项目（V0.5.8）并保存测试数据。
2. 解压新完整工程或把补丁目录内文件按相对路径覆盖原工程。
3. 运行 `scripts\build_windows.cmd` 检查 .NET 10 编译。
4. WPF 启动后确认三个保存目录互不覆盖；选择新的采集目录，采集几秒，验证文件落盘位置和 `imu_selected.csv` 模式。
5. IMU 保持连接状态，进入两台转台的独立页签测试扫描，确认扫描未对占用中的 IMU COM 发起连接；核对识别结果，再操作连接按钮。
