# 标定总目录与子文件夹规则（V0.5.6）

## 一次选目录，递归查找

在主窗口选择一个“标定总目录”。程序通过已读取的**12 字节 MCU 原始 UID / DTS 显示编号**，递归搜索该总目录及其任意层级的子文件夹。不需要逐项选择 JSON；CT-05 专用窗口也复用同一份匹配结果和同一补偿模式。

推荐结构（**不是强制结构**）：

```text
D:\IMU_标定数据库\
  DTS672516\
    常温\
      DTS672516_accel_calibration.json
      DTS672516_gyro_calibration.json
    全温\
      DTS672516_thermal_acc_candidate.json
      DTS672516_thermal_gyro_candidate.json
  DTS672517\
    ...
```

另一种存法：按日期 / 批次 / 研发组建立目录，也能匹配；程序**不根据目录名称猜 UID**，只匹配精确文件名并核实 JSON 内部的设备身份字段（如果有）。

## 补偿模式

- 两个复选框都不勾：**原始模式**。不需要标定文件。保存真实原始 int16 和 MCU 时间/状态；读取不到已核实量程时不假造 g 或 °/s。
- 勾选“常温标定”：匹配 `DTS编号_accel_calibration.json` 与 `DTS编号_gyro_calibration.json`。只应用常温模型；同时保存原始计数。
- 勾选“全温补偿”：匹配 `DTS编号_thermal_acc_candidate.json` 与 `DTS编号_thermal_gyro_candidate.json`。按 IMU 芯片温度应用全温模型；不得重复叠加常温模型；同时保存原始计数。

每次采集开始前冻结当前所选源文件的 SHA-256、参数快照和补偿模式。若源文件已被改动，拒绝启动补偿采集；开始后不会静默重新加载。原始 JSON 会以快照复制进该次运行目录的 `calibration_snapshots/`。所有采集始终记录 `imu_raw.csv`，在已选补偿模式下另外输出 `imu_selected.csv`。

## 多版本及冲突

1. 同一设备、同一类型文件只应有一个**生效版本**。如果递归发现同名不同内容的多份 JSON，会拒绝自动选择，并提示冲突路径。
2. 完全相同的副本（SHA-256 一致）可自动去重；选择的路径按稳定排序确定。
3. 历史多版本建议移至总目录之外的 `IMU_历史标定归档`。未来可通过“有效版本索引文件”设计支持同目录历史版本，目前未实现，不会猜测哪份更有效。
4. 只凭 `DTSxxxxxx` 短编号找到文件而缺少完整 UID 字段时，主窗口需人工核对 PCB 归属；如果 JSON 内有完整 UID 且与硬件不一致，则必须拒绝使用。
5. 明确带 `simulation_only: true` 的模板禁止用于真实设备补偿。
6. 使用本版真实补偿仍要求 MCU 上报可信物理量程；ACC_FS/GYRO_FS 无效时，可采原始计数，但不会生成伪造物理量或精度 PASS。

## 安全与设备

标定目录自动匹配不会产生任何转台运动；真实 CT-05 运动还必须独立通过设备反馈、量程/坐标系、轨迹范围和现场人员安全确认。自动递归跳过符号链接/目录重解析点，以免扫描到总目录以外的文件。

## 测试与限制

静态检查及内置自检新增了多层子目录、同内容副本和冲突版本的检查。但本交付环境没有 Windows/.NET 10 SDK 或实体 IMU/转台，**未完成 Windows 编译、UI 启动及硬件联调**。请在 Windows 上运行 `scripts\build_windows.cmd` 并确认实际日志及设备状态。
