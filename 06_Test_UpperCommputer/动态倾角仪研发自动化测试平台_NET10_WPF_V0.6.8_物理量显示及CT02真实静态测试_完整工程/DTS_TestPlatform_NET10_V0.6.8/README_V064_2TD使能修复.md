# V0.6.4 · 2TD-600 与 Python 上位机对齐的使能流程修复

本版从 **V0.6.3** 继续，保留 84 项测试、CT-05、IMU、温控转台及用户已有全部数据存储逻辑，仅调整 **2TD-600 建立通信后申请使能的流程**。

## 为什么之前能读角度却不能运行

Python 原版流程：`OpenPort → SetAxisEnable(0) → 等待100ms → SetAxisEnable(2) → 等待500ms → 轮询反馈`。
旧 WPF 将 `Normal==true` 作为**使能前**的必要条件。部分控制器尚未使能时可能不会报告该状态，因此进入仅诊断连接并且没有恢复使能的入口。

## 新版流程

1. 先按已有串口自动扫描和人工安全确认打开 2TD；**打开串口不等于已使能**。
2. 读取真实双轴状态；仅在两个轴都反馈**无故障、无已知限位、速度接近零**时允许请求使能。使能前 `Normal=0` 不是单独的阻止理由，但 `Fault` 未知时仍禁止发出使能。
3. 仿照 Python 先申请内轴使能，间隔 **100ms**，再申请外轴使能，然后等待 **500ms**。
4. 连续读取反馈；只有**连续两次**确认双轴 `Normal=true`、`Enabled=true`、没有故障，才把状态切换为可运动。
5. 如果使能失败或反馈未确认，保留串口作为**仅诊断连接**，禁止运动、归零和自动测试；显示完整原因并在 COM 栏显示 **「重新核验使能」**。点击它必须重新进行现场安全确认，绝不在后台偷偷使能。
6. 原有受控停车、断使能、断开连接与窗口退出拦截都保留；温控转台独立协议未变。

**现场首轮检查建议：** 先在厂家或 Python 原版软件中确认设备没有故障和限位，再关闭原版独占串口；用 WPF 扫描 COM，确认安全条件后连接。先验证状态和使能位，再在现场人员监督下小角度、低速（例如 1°、1°/s）试动。**不要用关闭程序代替停车；实体急停必须有效。**

## 实际改动文件

- `src/Dts.Devices/TdConnectionPolicy.cs`：使能前检查与使能后验证分离。
- `src/Dts.Devices/TdEnableWorkflow.cs`：新增可单测的状态机/使能时序。
- `src/Dts.Wpf/MainWindow.xaml.cs`：统一首次使能与手动重试、诊断状态、连接/断开控制。
- `src/Dts.Wpf/MainWindow.xaml`：仅诊断时显示「重新核验使能」。
- `src/Dts.SelfTest/Program.cs`：无实体硬件的使能顺序/故障拦截/部分使能失败重试测试。
