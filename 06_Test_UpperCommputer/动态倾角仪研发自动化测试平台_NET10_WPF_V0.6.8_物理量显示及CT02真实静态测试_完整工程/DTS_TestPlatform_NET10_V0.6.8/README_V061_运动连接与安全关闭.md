# V0.6.1：2TD 增量运动与安全连接生命周期（研发试用）

**基于 V0.6.0 修改。当前环境没有 Windows/.NET 10 SDK，未进行 Windows 实际编译或物理转台联调。首次应用必须先做静态反馈和低速小角度联调。**

## 1. 2TD-600

- 使用原厂 `2TD600.dll` 导出的 `SetAxisOpposition(int axis, double relativeDegrees, double speed)`；与原 Python ctypes 封装签名一致，厂家手册称为“增量位置”`0xD6`。
- 不再使用“当前位置 + 增量”来提交绝对位置指令，也不再人为限制 ±90°、0～360° 取值。
- 相对角度正负决定方向，速度输入为正，厂家手册规定为 0.01～60°/s；默认 10°/s。
- 保留真实故障/限位、非运动轴状态检查；**连续内轴旋转需要外轴保持零位**，必须现场核实轴间干涉与工装线缆条件。无限旋转不是无条件任意负载旋转。
- 操作员先勾选物理安全确认，再连接；连接流程会检查双轴静止/正常，自动发送使能并读取使能反馈，不会自动运动。
- 连接按钮在成功后变为“安全断开”；需检查双轴静止，确认断使能后才关闭 COM。

## 2. 2FDT600WK 温控转台

- 连接按钮切换为“安全断开”，断开流程要求发送双轴软停车、现场确认实际停稳、断使能后释放串口。
- 该 DLL 当前 `GetStateInfo` 的 `state` 值缺少确认后的状态位映射，因此**不宣称自动使能已验证**；保留请求使能/解除使能按钮。厂家状态协议核实后再启用“连接即自动使能”。
- 这台设备的机械范围和速度上限尚无独立可靠说明书证据；**不套用 2TD-600 的 60°/s**，暂保留此前保守的软件限幅，等待实机验证。

## 3. IMU 和程序关闭

- IMU 在无采集任务时，再次点击连接按钮会断开并释放串口；采集中不能断开。
- 正常关闭 WPF 时，如果任一转台仍连接，会阻止窗口关闭，提示先停车并安全断开。即便能够释放 COM，也不代表伺服已经停转。
- 转台物理急停和控制柜保护必须保持可用。进程强制关闭、系统掉电、串口拔插均无法保证自动执行安全断开步骤。

## 4. 现场验证建议

先连接但不运动，检查双轴使能回读和实际零速 → 发送 ±1°、1°/s 的小幅增量 → 检查正反方向与到位 → 测试跨 360° 的受控增量 → 提高至批准速率 → 验证软停车及安全断开 → 再启动 CT-05 等自动化测试。不要直接使用高速多圈运动作为首次测试。

当前仅源代码静态结构检查通过，未完成 Windows .NET 10 构建及物理设备验收。
