# V0.6.5 — CT-05 初始工况与标定数据显示修正

## 已经查明的四个区别

1. CT-05 X通道需内轴90°，但此前设置窗口默认行程上限30°，使得默认“小角度”扫描计划自相矛盾，禁止启动。本版默认上限改90°，仍需要现场机械安全确认。对称和全圈工况需要单独批准更大行程。
2. Python V1.4 的到位比较使用角度环绕距离（359.999°≈0°）；WPF 原先部分判定使用线性差，可能将正确到位误认失败。本版只修改**状态比较**，不擅自选择控制器实际走哪一侧。
3. WPF V0.6.4 归零用代码写死1°/s，并非10°/s。现在2TD有独立“归零速率”输入，默认10°/s，限制在说明书0.01~60°/s。温控转台归零速度仍是原有值，不能假设同样的范围。
4. 仅选择标定JSON不等于MCU已确认量程。原先FS=0或SENSOR_OK缺失时数据显示--。本版在IMU区提供**显式勾选**的“研发试算”，按当前UID常温JSON记录的量程将真实int16原始计数试算为g与°/s，再使用矩阵，输出`TRIAL_CALIBRATION_UNVERIFIED`。此数据不计入已验证样本，禁止正式验收。

## 设备与报告安全

- CT-05 在第一条运动命令前，新增真实IMU的SENSOR_OK/FIFO/FS前置检查。试算即便能显示数值，**CT-05仍要求固件量程和状态真实有效**。
- 试算的表格与`imu_selected.csv`使用相同的函数处理数值，另外总是输出`imu_raw.csv`原始计数。`manifest.json`新增`operator_enabled_unverified_scale_trial`和`provisional_trial_samples`。
- CT-05的扫描位置验证没有绕过正常位、使能位、到位位、反馈速度、人工运动确认或停车流程。
- 本版本不是出厂合格放行版本，不能凭试算结果开具准确度合格报告。

## Python V1.4 与当前软件的零位速度并不相同

Python V1.4 静态自动扫描速率默认2°/s，人工绝对定位控件默认1°/s；原WPF双轴归零写死1°/s；新WPF 2TD归零默认10°/s。它们不是同一项设定。CT-05自身的运动速度仍默认1°/s，独立于主界面归零速率。
