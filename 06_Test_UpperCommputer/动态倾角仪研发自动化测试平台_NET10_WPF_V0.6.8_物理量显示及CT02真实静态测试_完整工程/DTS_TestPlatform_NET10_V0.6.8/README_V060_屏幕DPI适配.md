# V0.6.0 跨电脑显示适配与实时数据窗口

## 现象与根因
同一 WPF 界面在不同 Windows DPI、屏幕工作区及字体设置下，分配到实时 DataGrid 的空间可能显著不同。V0.5.9 将主数据表放在剩余高度的 `*` 行内，前面的状态区、后面的采集按钮均占据 Auto 高度，在有效高度不足时会挤压表格。

## 本次改动
- 窗口最小逻辑高度降低，并对窗口高度低于 820 / 650 WPF 逻辑单位（DIP）的情况采用紧凑布局。
- IMU 状态信息改为可展开区域，低高度时自动收起，但不隐藏采集模式及安全重要信息。
- 添加「放大表格 ↗」按钮，打开独立的最大化实时六轴表格窗口；可同时观察与采集，读取的是主界面同一份实时数据集合。
- 添加 PerMonitorV2 DPI 感知 manifest，支持跨不同缩放显示器更清晰的重排。DPI 感知并不取代响应式布局。
- 仅修改 WPF 布局；不修改真实 IMU 串口协议、转台运动、UID、补偿及记录算法。

## Windows 必做显示测试
在测试电脑上分别核对 1920×1080（100%, 125%, 150%）、1366×768（100%, 125%）以及第二显示器不同 DPI 的运行情况。需确认：UID 可见、IMU 数据表可展开、采集按钮可点击、两个转台安全控制无裁切。

## 已知限制
当前环境不是 Windows，无法实际编译或运行 WPF。在 Windows 上用 `dotnet build src/Dts.Wpf/Dts.Wpf.csproj -c Debug` 验证，必要时提交第一条编译/运行异常和具体屏幕分辨率及 Windows 缩放值。
