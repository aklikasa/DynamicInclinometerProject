# V0.6.2 — 2TD-600 连接/使能分离修复

## 已定位的 V0.6.1 缺陷
- `TdConnectClick` 在厂家 `OpenPort` 成功后立即检查双轴 `Normal` 和瞬时速度，未确认即抛异常、尝试断使能、随后关闭串口。实际状态因此从可排查的数值退回 `--`。
- 上位机错误信息“无法连接”掩盖了“串口已打开但双轴自动使能条件未满足”的区别。

## 新流程
1. 被动扫描确认端口（COM2 等），安全确认后**仅建立串口连接**。
2. 等待最多四次只读状态轮询（间隔约250ms），显示详细双轴正常位、使能位、到位位及限位/驱动报警。
3. **仅当两轴正常、无故障、反馈速度接近零**才尝试自动使能；然后再次确认两轴使能反馈。
4. 任一条件未满足，**保留只读诊断连接，不发使能和运动命令**，界面显示异常位。此时“转台已连接”仅指通讯已建立，不代表运动可用。
5. 断开时只读/双轴未使能的连接仍须确认双轴停止与实体机械安全，才关闭串口；任何使能状态不明时保持连接并引导现场排查。

## 现场验证
- 关闭原 Python 上位机及厂家控制台，确保没有其他程序占用 COM2。
- 自动扫描识别 2TD → 勾选安全条件 → 点击连接。若进入只读状态，请记录状态日志中两个轴的正常位、驱动故障、限位、使能位、速度，不要尝试移动。
- 如果一直报正常位 0，使用厂家上位机在无运动工况下核实控制器实际报警/状态；排除状态报文尚未初始化或误读。**不要用删除 `Normal` 检查或强制 `SetAxisEnable` 的方式绕过报警**。
- 已正常使能后，现场监护、机械急停可用条件下，以小角度低速验证运动与停止。

## 验证边界
只完成源文件静态检查和纯函数安全策略用例编写，当前环境缺少 Windows .NET 10 SDK 与实体转台。此版本不是实机已验证的驱动升级。
