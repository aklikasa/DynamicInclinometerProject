# 后续如何直接往 V0.5 中补充一个测试项目

## 每项测试建议一套 6 个文件

以新测试 `CT-07` 为例：

1. `src/Dts.Tests/S1/CT_07_Test.cs`：执行 `ITestModule`，校验 UID、设备条件、调用真实采集、报告。
2. `src/Dts.Tests/S1/CT07/CT_07_Algorithm.cs`：纯数学，独立测试输入/输出，不引用 WPF。
3. `src/Dts.Tests/S1/CT07/CT_07_Result.cs`：输入设置、每次实际采样结果、统计与失败状态。
4. `src/Dts.Tests/S1/CT07/CT_07_Report.cs`：报表格式、UID/数据路径/算法版本与报告导出。
5. `src/Dts.Wpf/TestWindows/CT07/CT07Window.xaml`：独立设置页面和进度/结果展示。
6. `src/Dts.Wpf/TestWindows/CT07/CT07Window.xaml.cs`：WPF 页面事件，收集参数、通过 TestRunner 调度。UI 不应直接实现算法与原厂指令。

## 需要写注册代码吗？

**测试类不需要**：`TestModuleRegistry` 会发现实现 `ITestModule` 且存在公共无参构造函数的类。原有 84 个测试项目已经有占位类，建议直接填充/替换原编号的 `.cs`，避免同一编号有两份相互竞争的实现。

**独立测试窗体**：在窗口 Code-behind 上写 `[TestWindowFor("CT-07")]`，编译后主窗口按属性查找并打开。无需改主窗口的 `switch`。

**需要重编译**：把 `.cs` 和 `.xaml` 放进源码项目后，需要重新生成解决方案才会变成可运行软件。单纯把源文件放到 EXE 目录不会动态执行。

高级用法：算法测试模块编译为 `plugins/*.dll` 可在下次启动时被发现，但**不受信任的 DLL 不应加载**；WPF XAML 插件化页面尚未开放动态加载，新增专用 XAML 窗口仍需编入 WPF 工程。

## 报告实现原则

- 先选择项目根目录，按 UID 和测试时间建立唯一文件夹。
- 必存原始数据、算法输入、算法/参数版本、校准文件 SHA256、实测时间戳和有效采样数量。
- 通过/失败必须依赖明确验收标准和参考仪器信息；没有就只能写“待验收”。
- 取消、中断和异常也要有 `checkpoint.json` 与准确状态，不能只留下一个空文件夹。

## 真实设备安全原则

- 不能在测试模块中直接调用 `TdNative` 或 `FdtNative`，只能通过公共设备接口和安全调度。
- 使用实际反馈位置与新鲜状态，不将“命令返回成功”当成“机械已到位”。
- 自动运动前校验运动计划、硬件限位、急停、工装、电缆和设备可观测状态。
- 对尚未验证旋转方向、状态码及绝对/相对语义的设备，不得开放相应自动动作。
