# V0.5.8 实时数据表格、采集保存与两轴布局

## 一、界面操作

- 转台：两套转台均保留内/外轴独立相对运动、启停及归零，按钮在 2×2 区域留出 5 DIP 横向、6 DIP 纵向空隙；控制卡片不再用星号高度强行拉伸。
- IMU：右侧设备页签“IMU / 采集 / 补偿”中实时多行表格，显示批次接收时间、MCU Tick、批次内样本序号、Ax/Ay/Az/Gx/Gy/Gz、单位、温度及质量状态。内部滚动条仅用于**数据表**，不会遮挡转台运行/停止按钮。
- 仅在**IMU 实际连接成功**时从固件读取数据，未连接不会展示模拟数值。
- 最近最多 240 行实时展示。前台约每 220ms 更新一次批次快照，表格新行滚动到最新；不意味着只把预览帧写盘，CSV 写入每一个成功读取的样本。

## 二、显示模式就是主记录模式

三种模式互斥：

| 选择 | 表格显示 | imu_selected.csv 中 ax..gz 六列 | 单位 |
|---|---|---|---|
| 未勾选 | 原始 signed int16 | 相同原始计数 | count / count |
| 常温标定 | 当前 UID 的 ACC/Gyro 常温参数补偿值 | 相同的补偿值（六位小数） | g / deg/s |
| 全温补偿 | 当前 UID 的全温参数按芯片温度换算值 | 相同的补偿值（六位小数） | g / deg/s |

表格和主 CSV 共用 `Dts.Devices.SelectedImuFrame.FromSample()`、`ToSelectedCsvLine()`；避免以前实时预览和写盘分别计算的分歧。

**安全与数据可信度：** 如 MCU 未报告 SENSOR_OK、有效 ACC/Gyro 量程或温度超出模型范围，补偿模式的表格显示 `--`，主 CSV 六轴列也写 `--`，同时记录明确的状态码。绝不回退显示 raw 而让操作员误以为已标定。未验证的数据不可用于正式精度验收。

## 三、输出文件

- `imu_selected.csv`：**主记录**，每帧均按“显示/记录模式”写入；raw 模式同样生成。
- `imu_raw.csv`：独立原始备份，始终包含 MCU 六轴原始计数，支持以后重新标定及重算。
- `manifest.json`：记录原始 UID、DTS 编号、运行模式、文件名、量程/状态统计、参数文件哈希和开始/结束状态。
- `calibration_snapshots/`：采用补偿模式时保留实际参数文件快照。

说明：`host_utc` 是本批次接收时间；MCU Tick 是批次 Tick，不保证每条 FIFO 样本存在独立同步时标。表格为了性能只显示最近的部分帧，文件保存全部真实采集帧。

## 四、现场回归顺序

1. 不打开运动控制，只连接 IMU 并读取真实 UID，观察表格 raw 数值是否持续追加、滚动。
2. 原始模式采集约 10 秒；验证 `imu_selected.csv` 的六轴数值与表格对应、单位 `count`，`imu_raw.csv` 同时存在。
3. 选择全局标定目录，核对匹配 UID 与 ACC/Gyro 常温参数，选择常温模式；核对状态无误后采集；对比表格与 `imu_selected.csv` 每帧六轴列的一致性。
4. 全温模式重复；检查温度超界保护及 `manifest.json` 参数文件哈希。
5. 检查已知故障状态：MCU 的 ACC_FS/Gyro_FS 为 0 或 SENSOR_OK 未上报时，不允许输出伪装为正式补偿的数据。
6. 在安全操作条件满足且原厂家转台通讯已通过现场验证后，检查两轴按钮空隙、归零及状态的可见性。本版没有修改任何厂家 DLL 运动指令。

本工程在非 Windows 环境完成了静态检查；**未完成 Windows .NET 10 实际编译或实机验收**。
