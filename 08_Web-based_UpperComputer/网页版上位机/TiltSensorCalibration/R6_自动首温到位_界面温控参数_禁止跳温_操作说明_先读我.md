# R6修订：开始后一键自动到首温 + 温控门槛可设置 + 禁止跳过温度/工况

本工程从用户上传的R5完整工程修改。**不要在正在运行的旧版本上覆盖.py后热更新。** 停止当前任务并安全核查转台/温箱，备份原始实验数据，解压本工程到**新的目录**，由现场人员验证后再使用。

## 你最关心的操作

1. 先打开原上位机，通过已经安装并实测的Snap7 PLC连接温箱；连接WK转台及IMU，确认两轴处于静止安全状态。
2. 进入 **IMU自动温补**，选择PLC自动控温，选择升温/降温/双向计划并加载协议。
3. 在新增的 **“启动后PLC自动到首个温度”** 区域，保持勾选“自动分段设温到第一个/续做温度”。默认中间SP从当前**PV起点**每级向目标前进5℃，每一级要求PLC SP回读，PV进入阶段SP±1℃连续5秒，再前进下一级；每级60分钟超时则中止整个实验并保留数据，不自动跳温。首次/断点续做均执行该流程。
4. 在 **“温补温度策略”** 中可以分别设置：初步到温PV允许偏差、共同热浸PV允许偏差、最终PV允许偏差及持续时间、芯片稳定门槛；在 **“运行中温度质量阈值”** 中可以设置PV暂停偏差和超限时间、芯片温度极差/斜率及恢复门槛。默认“运行期间PV暂停偏差跟随最终PV允许偏差”，例如最终填写±2.2℃，则运行期PV暂停判据也使用2.2℃，不再隐藏为1.0℃。
5. 检查保护、量程、现场安全确认及厂家允许热冲击后点击“启动自动温补实验”。**不需要人工先把PV调整到第一个目标±8℃。** 自动到温过程中WK一直停车；到达正式目标温度后，按“初步稳定→共同热浸→最终PV连续稳定→芯片60秒稳定”的质量门槛逐项通过才会开始ACC/GYRO采集。
6. 如某温度点/工况无法完成，程序只会进行有限安全补测，或安全中止并保存INCOMPLETE/断点；**绝不自动跳到下个温度，也不把缺失当成生产合格**。要续做时选择原THERM任务文件夹，按界面提示启动恢复。

## 各阶段不同的温度范围（不要混用）

- **中间自动到温阶段：** PV需进入临时SP±1℃连续5秒，才能发送下一个中间SP；这是流程推进条件，不是允许ACC/GYRO标定的条件。
- **初步到温：** 根据模式初始化为严格恒温±1.0℃、研发连续±1.5℃，均可在界面修改；同时需要连续观察时间、PV极差和PV斜率符合门槛。
- **热浸：** 严格恒温默认±1.0℃、研发连续±1.5℃，界面可修改；仅统计PV在允许范围内的有效热浸时间。
- **最终准入：** 界面“最终PV允许偏差”与连续观察时长，另加IMU芯片温度稳定和芯片-PV合理性门槛（代码仍检查`abs(chip-PV)<=10℃`）。
- **运行时停机条件：** 使用“运行中温度质量阈值”区块的冻结值；与前述初步/热浸/最终门槛分别记录。

如果你把“最终PV允许偏差”设为±2.2℃但“初步到温”仍设±1℃，那么程序仍要先满足±1℃的初步门槛。这不是偷用1℃的运行期停机条件，界面会将各阶段分别显示。

## 注意：逐级SP不是厂家认证的温度斜坡控制

程序复用现有PLC定值模式、SP写入、定值启动和SP回读，不引入未经验证的PLC厂家斜率指令。**每级5℃表示以当前PV为起点规划中间设定值，不能保证温箱实际升降温速率不超过5℃/某个时间，也不一定意味着PLC原SP与新SP的差始终≤5℃。** 请现场依据温箱说明、PCB热冲击、冷凝/除湿要求审核允许速率，并优先使用厂家合规的程序升降温功能。如果厂家禁止运行中频繁改变定值SP，应先完成设备接口验证，不要用于无人值守生产实验。

运行中依然保留原始PLC报警、实时PV/SP新鲜度、WK状态、速度/位置、IMU读数/队列数据丢失和停止确认的硬保护。参数可编辑不代表覆盖设备独立硬件安全策略。

## 软件质量确认

- R6初始分段设温状态机：25→−40℃的13次SP请求模拟、SP异常回读超时中止、禁止启用WK运动，离线测试通过。
- 初温规划、运行质量策略约束、禁止缺失工况推进：纯Python单元测试通过。
- 旧R5“自动跳温”回归断言已按新生产规则更新；无新的实际PLC/WK机器测试。
- 原工程其余部分仍保留，包括厂家DLL、原温补模型和报告；没有证明自动变更SP的机械/温箱物理性能，须先有人值守低风险调试。

## 运行入口

`TiltSensorCalibration/main.py` 或 `TiltSensorCalibration/START_WORKSTATION.bat`（Windows）。需按原工程依赖安装。正式部署前在相同设备上人工验证：连接和报警、SP分级变化、PV跟进、停止/断电恢复和中途断点续做。
