# 动态倾角仪上位机——温补自动模型优选升级说明（2026-11-05）

## 交付内容

这是在用户上传的完整 Python/PySide6 上位机源码基础上修改的工程，**不是已在 Windows 实机上验证的 exe 安装包**。

### 四项需求的实现

1. **一/二/三次温度多项式自动比较**：依据每温度点的已采集数据生成候选模型；温度自变量为 IMU 自测芯片温度，参考温度中心 25°C。
2. **仅零偏 / 零偏及比例因子 / 完整3×3矩阵**：三类温补、各 1/2/3 次，另加实测最接近 25℃ 拟合温度的固定参数基准 A0，共 10 种候选。ACC/GYRO 独立选型。若25℃属于拟合温度，就使用25℃实际拟合参数；不读取其他常温标定 JSON。现有完整三次标定文件继续保存。
3. **自动选优和独立温度验收**：只用拟合温度下的独立工况数据选型，打分 = 独立工况向量RMSE×(1+0.02×次数+0.025×模型复杂度)，模型复杂度A=0、B=1、C=2、D=3。完成排序后才检查独立温度测试数据。若独立温度RMSE或最大误差未改善，输出“未改善、不建议采用”，**绝不用最后的温度测试结果重新挑赢家**，防止测试泄漏。
4. **补偿前后静态倾角对比**：使用 ACC 独立静态姿态的**重力矢量方向夹角误差**计算RMSE/最大误差/改善率，分温度列出。不能将它误称为整机动态融合倾角精度。**动态倾角**需要同步的ACC/GYRO、转台姿态时间序列与实际产品融合算法，当前明确标为“尚无有效评价”，不会捏造结果。

### 软件页面变化

- 原“IMU 自动温补”页：温补采集完成后，在任务界面显示 ACC/GYRO 自动选型的编号和独立温度验证结果；所有模型仍标记“研发候选，禁止直接量产放行”。
- 新增按钮：**“离线重新分析已有完整温补实验（不控制设备）”**。选中包含 `temperature_measurements.json` 的已完成 `THERM_*` 实验文件夹后，会在该实验目录下生成新的 `模型优选离线复算_时间戳` 子目录，不覆盖原始数据。
- 不修改既有温度设定与热平衡状态机、手动转台控制、WK停止确认、ACC/GYRO采样顺序和动态速率参数。原10°/s手动/常温限制及温补独立60°/s高速工况逻辑未变；温补高速运动**仍需现场核实机械行程、线缆/滑环与厂家限额**。

### 输出文件

温补完成的实验目录，新增：

- `thermal_model_selection.json`：10种模型的选型依据、误差、独立温度验收与状态。
- `thermal_acc_model_candidates.json`、`thermal_gyro_model_candidates.json`：各候选模型的实际系数。
- `thermal_acc_selected_candidate.json`、`thermal_gyro_selected_candidate.json`：自动排名选出的研究候选及是否通过独立温度验证；不会写入MCU/PLC，也不会替换常温标定文件。
- `thermal_calibration_report.xlsx`：保留原《温补总览》《逐工况测量》，增加《模型自动比较》《逐温度误差比较》《静态倾角精度对比》《结论与数据边界》。
- 原 `thermal_acc_candidate.json`、`thermal_gyro_candidate.json`、`thermal_fit_status.json` 等文件继续保留以兼容既有流程。

## 在 Windows 上运行

保留原工程全部 DLL、配置、UI、Python 代码。确认 Windows 环境、Python 版本和原工程依赖可用后，双击 `START_WORKSTATION.bat`，或在项目根目录运行 `python main.py`。上位机依赖 `PySide6`、`numpy`、`openpyxl`、`pyserial`、`python-snap7` 等；请沿用当前能驱动设备的 Python/驱动环境，**不要随意升级现场设备 DLL**。

算法和 Excel 功能可以直接运行 `RUN_THERMAL_MODEL_SELECTION_TESTS.bat` 离线测试，不需要连接任何 PLC、WK 转台、IMU。

## 验证与已知限制

- 代码已在非 Windows 环境完成静态编译、合成数据算法测试、报告表格测试和既有离线回归测试；没有连接真实 PLC、转台、传感器，也没有执行 Windows Qt 界面启动验收。
- 原始ZIP的37个离线测试中，有2项（`test_2fdt_zero_status.py`、`test_stable_base_regression.py`）**在原始工程上就已经失败**：分别是旧转台回零 UI 字符串断言、旧转台控制文件的SHA256基准不一致。本次未修改这些硬件控制文件或伪造测试基准。
- 研发模型不自动认为合格，也不自动写入生产标定参数。只有通过全温、动态整机、硬件安全联调及正式门限验收后，才能考虑量产导入。
- 现有温度计划默认拟合温度只有4个；三次曲线刚好插值这些点，仍可能温度过拟合。增加拟合/独立验证温度点可提升选型稳健性。
