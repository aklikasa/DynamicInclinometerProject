# 2FDT600WK 如洋温箱：复用原 PLC 的全自动温补（研发集成版）

## 1. 本次为何启用 PLC 自动温控

用户明确确认，**原上位机“温箱”页面在这台如洋温箱上已成功读取实际温度、写入目标温度并产生真实升降温**。因此这版温补默认使用原 `temperature_chamber/temperature_chamber_comm.py` 中的 Snap7/PLC 控制路径，不再默认人工逐点设温。该现场事实是启用此接口的前提；并不意味着所有 2FDT600WK 都使用同一 PLC 地址表。

原工程沿用的读写接口：

- `tc_pv_get`：PV，VW2100；`tc_sp_get`：SP 回读，VW2106；`tc_sp_set`：SP 写入，VW2110；温度放大 10 倍；
- `tc_set_fixed_value_mode`：V2130.2，设为定值模式；`tc_fixed_value_startup`：V954.0，启动定值运行；`tc_fixed_value_stop`：停止定值运行；
- `tc_run_state_get`、`tc_fixed_value_state_get`、`tc_alarm_value_get`、`tc_device_fault_state_get` 读取运行及报警；
- PLC IP 在原温箱页面由操作者输入并连接，原默认值 `192.168.0.10`，实际应以现场为准。

**没有新增任何猜测性的如洋 RS-232 写命令。** 若现场温箱不是已验证的这套 PLC，必须选择人工模式或先完成协议确认。

## 2. 本次实际修改和新增

- `form/form_thermal_compensation.py`：温箱模式首选 **PLC 自动控温**；增加“原温箱页面已经实测设温成功”确认项；每温度点自动下发定值模式、SP、启动指令 → 必须回读 SP 且确认运行状态 → 实时 PV 连续 30 秒在目标 ±1°C → 等待芯片温度热平衡 → 自动转台采样 → 下一温度点；默认完成后自动返回 25°C，并等 PV 回到 25±1°C 连续 30 秒。全部设备参数在运行时锁定，人工模式仍保留为备选。
- `temperature_chamber/temperature_chamber_data_get.py`：在真实 PLC **读取成功**时分别为 PV/SP/报警/故障/运行状态打单调时间戳，PV 读取失败时清除有效标志；解决旧缓存温度被误认为温箱仍正常的问题。
- `chamber_auto_guard.py`：不依赖界面与 DLL 的温箱安全门禁；连接/PV/SP/报警/状态的新鲜度要求（默认 15 秒）、温度数值边界、故障报警、SP 回读差（0.2°C）、定值模式和运行启动反馈核查。
- `form/form_tc.py`：保存实际使用的 PLC IP 进入实验记录。
- `tools/test_chamber_auto_guard.py`、`tools/test_plc_auto_page_wiring.py` 和 `tools/test_plc_auto_state_machine.py`：离线安全单测、UI 静态链路及自动设温/到温/回25°C 状态机模拟。
- 现有 2FDT DLL、IMU 采集、温度补偿模型、A/B/C 对比和报告全部保留。

## 3. 操作方法（首次仍需现场监护）

1. 原温箱页面：连接以前**已经用过且确认能设温的** PLC/IP；查看 PV、SP、运行及报警反馈是否持续更新。请勿在有工件风险的情况下试写未知地址。
2. 原转台页面：连接 **2FDT600WK**，核对轴方向、机械限位、配平、硬件急停、零位与位置反馈；原 IMU 页面确认连续原始测量、量程、ODR 和芯片温度。
3. 打开 **IMU 自动温补**，温箱方式选择（默认）`自动控温：使用原上位机已验证的 Snap7/PLC 温箱`。填写 PCB 唯一编号、温度点和保存位置。
4. 首次建议**关闭动态 GYRO**，先做静态 ACC/零偏实验，并现场观察第一次设温和第一批姿态的停车与方向。通过后再启用动态工况。
5. 逐项完成全部安全确认及“原温箱页面已真实设温成功”的确认，点击 **启动自动温补实验**。**无需逐温度点输入 PV、手动点到温确认。**
6. 程序不采用定时猜测到温：必须达到 PV 及 IMU 内温稳定门限，且温箱 SP 回读、运行状态、报警、反馈更新均正常，才会执行转台动作。
7. 最后一个温度点全部完成后，默认自动将 SP 改为 25°C，等待 PV 返回稳定范围，结束任务并生成温补候选和验证报告。可在页面显式取消此行为，但会在最后温度点保持原温控设定，必须由现场人员处置。

## 4. 安全行为与未验收边界

- PLC 通信断开、PV/SP/报警/运行反馈超过 15 秒无更新、PV 读取失败、报警值非 0、温箱故障、SP 回读不匹配、未进入定值运行、IMU/转台失联或转速不达标，均触发中止，防止继续采集或运动。
- 软件中止时向两轴发送停车指令，在 PLC 自动模式下额外**尝试**停止温箱定值运行；如断线，停止命令可能失败。**必须由现场人员确认转台已停止和温箱真实状态；硬件急停独立有效。**
- 最后完成后回到 25°C 并不代表温箱已经关闭动力或工件完全处于可触摸安全温度；必须遵守现场安全规程。
- `OFFLINE_DEBUG` 模式禁止启动真实温补。
- 保留人工设温模式，适用于 PLC 通信真正不可用时，但不等于自动控温。
- 转台编码器位置差分获得的速率仍需实机精度验证。**当前环境无法运行 Windows DLL，也未安装 PySide6/PLC 设备，因此不宣称完成真实设备或无人值守验收。**
- 所有温补文件均为候选，不会覆盖常温标定参数或自动写入 MCU 量产区。

## 5. Windows 自测

运行 `Windows_自动温补离线自测.bat`。该脚本会运行语法/数值/报表/旧版回归，以及自动PLC控制逻辑的离线安全单测。单测不会连接真实温箱，也不会下发运动命令。
