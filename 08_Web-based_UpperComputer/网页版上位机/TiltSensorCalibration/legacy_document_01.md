# 2FDT600WK 双轴温控转台：IMU 自动温补开发集成版

## 1. 本轮实际新增的源码

在用户上传 `(10).zip` 原项目上修改；不迁移 WPF。主入口 `main.py` 新增 **IMU 自动温补** 标签页。

- `form/form_thermal_compensation.py`：原位 PySide6 温补页、温度调度、机械预检查、操作者安全确认、真实 2FDT DLL 运动、IMU 队列读取、热平衡监测、静态/动态工况、有限重试、异常停车、自动记录。
- `thermal_compensation.py`：每温度点 3×3 全矩阵 + 零偏求解；以芯片内温为自变量的线性温度模型；**不同姿态和不同温度点的独立留出验证**；25°C 固定参数对照；禁止温度模型外推。
- `thermal_excel_report.py`：研发用 Excel 概览、逐工况记录。
- `turntable/turntable_data_get.py`：对 2FDT600WK 补上位置反馈差分的转速估算，避免继续使用原始一直不更新的 `inner_axis_speed`、`outer_axis_speed`。速率不是原厂测速认证，需实机计量。
- 原有 `form/form_imu_calibration.py` 合并了此前 Python A/B/C 三方案版本（默认 C）；带回 `calibration_model_compare.py`、`model_comparison_report.py` 及测试脚本；保留原常温功能。
- 原有 `2FDT600WK.dll`、`2TD600.dll` 原样保留，不修改 DLL。

## 2. **最新补充：现场已验证的 Snap7 PLC 可用于如洋温箱自动设温**

用户后续确认：原温箱页面曾对**正在使用的如洋温箱**成功读取PV、写入SP并产生实际升降温。因此本工程最新版本默认复用**已验证的原 Snap7 PLC 驱动**，不需要手工切换温度点。温补过程新增 PV/SP/报警和运行状态的数据新鲜度、SP 回读、回温 25°C 等安全检查；具体说明见 `README_原PLC温箱_自动温补_使用与安全.md`。

原说明书虽单列 RS232 接口，但本次不使用未确认的 RS232 命令。对于未使用这套现场已验证 PLC 的温箱，仍需重新确认接口，不能直接套用本项目 PLC 地址。

## 3. 第一次实际使用顺序（必须有人员监护）

1. 在 Windows 上安装现有项目已要求的 Python、PySide6、numpy、openpyxl、pyserial、python-snap7，确认 **64 位 Python** 能加载原 DLL。不要在 Linux 或脱离硬件的开发环境点击运动按钮。
2. 按说明书安装并配平负载、核实所有轴的机械锁处于松开状态，测试现场硬件急停。核实 2FDT 内外轴的**实际物理方向、正转符号、机械零位、水平参考和用户坐标系**。如果这些不一致，先不要自动标定。
3. 原“转台”页选择 **2FDT600WK**，按现有原软件双轴端口配置连接设备，完成找零并确认两轴实时角度反馈有效；原 IMU 连接区连接 ASM330LHHX 并确认量程/ODR/芯片温度持续更新。
4. 点击新标签 **IMU 自动温补**。输入 PCB 唯一编号、温度点、数据目录。默认五点 `-20, 0, 25, 45, 70`（依序从低到高），第 1/3/5 点用于温度模型拟合，第 2/4 点**只作为独立温度验证点**。更改温度点时仍需确保覆盖设备允许范围、同等安全条件和足够热平衡。
5. 首次建议**取消勾选 GYRO 动态速率温补**，先测试温箱内 2FDT 的小角度定位与 ACC 多姿态采样，以及 GYRO 静止零偏温漂；成功后再勾选 GYRO 多速率工况。
6. 首轮检查默认每姿态 5 秒，位置速度 2°/s，静置 3 秒，热平衡等待最短 1800 秒；热平衡不仅看等待时间，还要看芯片温度在最近 60 秒内波动不超过 0.2°C。这些是研发起始值，不是仪器计量合格标准。
7. 确认全部安全项、以及在这台如洋温箱上曾通过原温箱页真实设温的复核项，点击“启动自动温补实验”。**默认 PLC 自动设温，逐点核查 SP/PV，无需人工逐点设置**。若主动选择人工模式，则仍需要逐点确认。页面“中止并停车”和硬件急停必须随时可用；软件停车不等同硬件急停。
8. 完成后查看新实验目录。只使用质量合格、实机校准参考正确且留出验证有效的结果继续研究，**不要直接写入 MCU 量产参数**。

## 4. 每个温度点自动采集内容

- **ACC**：12 个拟合姿态 + 12 个不重复的独立验证姿态。
- **GYRO 静止**：拟合/验证各一个零速工况，包含 45 秒/10 秒采样（按原工艺设置）。
- **可选 GYRO 动态**：沿内外轴组合产生三个互相独立的参考方向：拟合 ±1、±2、±5°/s，共 18 个动态工况；验证 ±1.5、±3.5°/s，共 12 个工况。参考转速来自 2FDT 编码器位置差分反馈，**不允许仅用下发转速作为测量值**。
- 共 **26 个静态工况/温度**，选择 GYRO 动态后共 **56 个工况/温度**。
- 每工况采用稳健 MAD/3Sigma、有效帧数、转台反馈时间、静止/匀速稳定、芯片温度跨度检查；质量失败最多重试两次（包含首次共三次），失败中止。

## 5. 输出与标定数学

在 `THERM_YYYYMMDD_HHMMSS/` 下生成：

- `experiment_config.json` — PCB/工艺/温度分组/设备模式/安全基准快照。
- `imu_full_frames.jsonl` — 连同 16 个原始采样数组和时间戳的逐帧记录。
- `imu_frame_means.csv` — 逐帧稳健均值、反馈角度和估算速率、芯片温度等。
- `temperature_measurements.json` / `.csv` — 每个完成工况的统计数据以及异常事件。异常中止时也保留已采结果，标记 `INCOMPLETE`。
- `thermal_acc_candidate.json` — ACC 原始值到平台比力的完整 3×3 温度补偿候选（仅所有拟合/验证条件满足时创建）。
- `thermal_gyro_candidate.json` — GYRO 完整 3×3 温度补偿候选，仅在勾选动态 GYRO 且所需数据齐全时可拟合。
- `thermal_gyro_bias_only_candidate.json` — 静止 GYRO 零偏随温度变化模型，**不含比例因子温补**。
- `thermal_fit_status.json` — 每个模型拟合成功、失败原因及独立验证结果。
- `thermal_calibration_report.xlsx` — 温补结果、25°C 固定模型对照及逐工况表。

求解模型：`raw = F(T_chip) @ reference + b(T_chip)`，`corrected = inv(F(T_chip)) @ (raw - b(T_chip))`。温度拟合在不同拟合温度上对全矩阵/零偏分别拟合，**温度验证和工况验证都不参与拟合**。采用一阶温度模型（高阶模型应另行评审），禁止温度范围外外推。

报告中的“25°C 固定矩阵”是将**本次温度模型在 25°C 的参数固定**作为未温补对照，**不是直接从原常温 C 方案 JSON 导入的参数**。这次原常温文件不会被覆盖；新的模型也不会自动部署到设备。

温箱的 ±2°C 偏差不等于芯片温度计量精度，必须现场校核参考温度传感器。暂不能据此签署量产放行。

## 6. 已完成测试与尚未完成事项

已在本环境通过：Python `compileall` 静态语法检查；温补纯数学 7 项测试（含数据分组隔离、外推拒绝、完整矩阵/零偏拟合）；工况与页面静态连线检查；温补 Excel 自测；旧版 ACC/GYRO 工况、3Sigma、模型对比、异常路径等原测试。
