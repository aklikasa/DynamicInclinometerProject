# 动态倾角仪上位机——28套温补联合优选最终版

版本：2026-11-05，Python/PySide6 完整源码工程，**不是 Windows EXE**，未完成真实硬件验收。

## 1. 使用方式

在原设备 Windows 电脑保留现有 Python 环境、转台 DLL、温箱PLC连接及驱动。进入 `TiltSensorCalibration`，双击 `START_WORKSTATION.bat`。

先执行 `RUN_THERMAL_MODEL_SELECTION_TESTS.bat` 完成离线算法/报告测试。不控制设备。现场温补应确认 PLC/SP/PV、IMU量程与ODR、转台反馈和硬件急停；特别注意最高60°/s工况、线缆/滑环与连续转角，不要仅凭软件10°/s姿态移动限速认为动态工况也被限制。

在 `IMU 自动温补` 页面运行完整实验。温箱SP→实测PV稳定→芯片温度稳定→ACC拟合/独立姿态→GYRO静态零偏及三轴正反转拟合/独立速率→每温度保存→下一个温度。保留原运动状态机、PLC控制与采集质量阈值；温补采样质量失败的重试次数已和常温标定统一。

实验采完自动拟合并在原目录生成结果。也可点击“离线重新分析已有完整温补实验（不控制设备）”，选已经完成的实验文件夹，以新分析子目录输出28套结果。离线复算必须能读取原实验的 `imu_frame_means.csv` 才能尝试PV校正模型；若没有可信PV将禁用T1/T2，不会拿SP冒充PV。

## 2. 候选模型总数

- `A0`：最接近25℃的**本次温补拟合温度的实测标定参数**固定使用，作为常温固定基准；不是外部常温标定文件。
- 温度输入 `T0`：直接使用IMU原始芯片温度。
- 温度输入 `T1`：在实验的拟合温度工况建立**芯片温度→PV等效温度**的线性校正。
- 温度输入 `T2`：同样建立二次校正，必须单调、稳定、温差和数值条件合格。
- 参数结构 `B`：温度相关三轴零偏，矩阵固定。
- 参数结构 `C`：温度相关零偏+三轴对角比例因子，非对角耦合保持固定。
- 参数结构 `D`：温度相关零偏+完整3×3矩阵。
- 阶数 `1/2/3`：一次、二次、三次温度多项式。

总共 `A0 + (T0/T1/T2) × (B/C/D) × (1/2/3) = 28` 套候选，ACC和GYRO分别评估（报告共56条候选行）。模型不满足数据要求会显示“不可用原因”，不是28套一定都合格。

**注意：T1线性温度校正并不会提高同阶多项式在数学上的表达能力。** PV等效温度不是实际芯片结温的绝对真值；模型最后只根据真实IMU误差决定是否选用它，评分会对附加复杂度给予轻微惩罚。

## 3. 模型与MCU温度公式

T0直接令 `T_eff = T_chip`。

T1/T2以芯片温度为输入（°C），校正系数定义为：

`u = (T_chip - 25)/50`

`T_eff = 25 + sum(c[k] * u**k)`

对某个补偿参数（矩阵元素或零偏）：

`p(T_eff) = sum(p_coeff[k] * (T_eff - 25)**k)`

传感器补偿：`reference = solve(F(T_eff), raw - b(T_eff))`。

**产品实际运行只读取T_chip，不需要也不允许依赖温箱PV。** `thermal_acc_selected_candidate.json` 与 `thermal_gyro_selected_candidate.json` 中的 `temperature_input`、`bias_coeff`、`forward_coeff` 共同决定最终公式。导入MCU前必须检查轴定义、单位、数值精度、温区边界及矩阵条件数；上位机不会自动写入MCU。

## 4. 严格分离拟合、排名与验收

1. **拟合温度的拟合工况**：求各温度的3轴参数；只用这里对应的PV+芯片温度来训练T1/T2，不允许碰独立验证温度PV。
2. **拟合温度的独立姿态/速率工况**：为有效的候选计算RMSE和最大误差；根据RMSE和模型复杂度评分冻结ACC、GYRO排名。
3. **独立验证温度的独立工况**：冻结排名后再测试是否比A0改善；失败不回头利用验收数据改选第二名；不等于已通过产品验收。

所有选择都是研发候选，`production_release=false`。

## 5. 数据充足性保护（非常重要）

为了避免多项式纯插值，1/2/3次温补**至少要3/4/5个参与拟合的温度点**，并且还必须有独立验证温度。PV校正T1至少3个可靠拟合温度点，T2至少4个，且PV关系必须基本单调。

默认5个温度点 `-20,0,25,45,70`：拟合 `-20,0,25,70`，独立 `45`。因此可评价有效一次和二次候选，**三次候选会显示“数据不足”**（原遗留的三次模型文件仍有可能生成，但它不参与28套安全选优）。

推荐的研发温度点例如 `-20,-10,0,15,25,40,55,70`，当前分组为5个拟合温度和3个独立验收温度，能够尝试全部28套；还应增加升降温重复性实验以检查热滞回。不要仅为凑齐数学点数而降低单温度热平衡和测量质量。

## 6. 输出报告

- `thermal_model_selection.json`：28候选清单/每种传感器选中编号、每套模型“可用/不可用”原因、选型工况误差、独立温度验证、PV来源及T0/T1/T2校正系数。
- `thermal_acc_model_candidates.json`、`thermal_gyro_model_candidates.json`：各个**成功拟合候选**的全部系数。
- `thermal_acc_selected_candidate.json`、`thermal_gyro_selected_candidate.json`：按选型规则排名第一的研发候选系数；字段 `selection_status` 表明是否通过独立温度检查，不可将输出文件存在当成量产放行。
- `thermal_calibration_report.xlsx`：温补总览、逐工况测量、模型自动比较（ACC/GYRO共56条候选）、芯片温度校正与训练数据、逐温度误差比较、静态倾角精度对比、结论与数据边界、MCU部署说明。
- 原三次候选、原始全帧CSV/JSONL、快照及配置文件继续保留。静态倾角基于ACC重力方向角；动态ACC/GYRO融合倾角尚需真实整机解算算法和同步参考，不能用三轴角速度RMSE冒充。

## 7. 离线验收与风险

- 无硬件环境可做Python编译、合成数据、无PV/异常PV、离线历史CSV回放、模型训练/最终验证隔离、Excel报告格式测试。
- 本次未连接真实WK转台、PLC温箱及IMU，未在Windows下驱动DLL或启动Qt运行；必须由现场完成首次启动、温箱控温、速度/零位/停车/急停、报告与MCU部署一致性验收。
- 来自上一个交付ZIP的两项遗留回归断言（旧转台回零状态源代码文本、旧控制文件SHA哈希）在上一个ZIP原本就失败；为了不触碰实机运动控制代码，本次未更改转台控制源码或修改这些旧测试的“期望结果”。

## 8. 推荐的现场试运行顺序

先在不连接危险运动的条件下运行离线算法测试；再通过上位机的“离线重新分析已有完整实验”验证PV曲线和结果；接着按现场SOP低风险工况试运行并检查停止反馈；最后才实施完整多温度实验。**切勿将离线通过解释为硬件安全认证。**

## 9. 温补采样质量失败重试策略（与常温标定统一）

- ACC静态姿态及GYRO静态零偏：**首次采样 + 最多5次重试**；第6次依然未通过才中止温补任务。
- GYRO动态速率：**首次采样 + 最多3次重试**；第4次依然未通过才中止温补任务。
- 直接复用 `production_quality_profile.json` 的 `quality.static_sample_max_retries` 与 `quality.rate_sample_max_retries`，不是温补单独写死次数。修改工艺配置前需评估。
- **只对 `robust_segment` 报出的采样质量不合格进行重试**，不合格段不进入参数拟合与模型选型。通信、伺服报警、方向错误、超速/停车故障等安全异常仍按原逻辑直接中止。
- 静态重试仍需重新确认姿态到位后静置；动态重试仍需下发停车命令，等待WK两轴返回1#伺服待命并连续稳定后再重新定位采样，不允许跳过停车确认。
- 温补每工况芯片温度极差上限保持 **0.5℃**（常温为1.0℃）；ACC/GYRO噪声、离群帧和转台速度判据未更改；28套模型、独立验证和Excel报告未改。
- 增加重试机会不意味着已验证的传感器精度必然不变：反复采样可能延长温箱内实验时间，原有质控只保证单工况阈值，因此仍建议现场复查长时间温漂和中止停车安全。
- 可在 Windows 运行 `RUN_THERMAL_MODEL_SELECTION_TESTS.bat`（新增重试策略离线回归）；也可以单独运行 `python tools\test_thermal_retry_alignment.py`。这些测试不涉及现场实机验收。
