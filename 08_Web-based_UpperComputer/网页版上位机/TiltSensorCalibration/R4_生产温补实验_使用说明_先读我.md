# WK双轴转台·六轴IMU −40～85℃双向温补 R4

> **工程试验版本，不是已经验证的量产放行系统。** 本软件保留原有真实WK DLL、PLC、IMU采集、原28套模型报告，新增双向生产研究试验、组合式几何+温补选模、热滞后/温度质量/六轴坐标报告。没有完成外部角度基准、PCB实机和六轴融合动态校验前，不允许直接把研究系数写入MCU，更不能声称产品已通过−40～85℃认证。

## 1. 最简单使用方式

1. 在Windows解压**整个**工程ZIP，不可只拷贝main.py。使用原来能运行该设备的Python环境；另需 `numpy scipy`、PySide6及原工程原有依赖。
2. 双击 `运行R4上位机.bat` 或从 `TiltSensorCalibration` 目录执行 `python main.py`。
3. 进入 **IMU自动温补** 页，找到新加的 **R4 −40～85℃双向温补** 面板。
4. 第一次选“**升温 −40→85℃**”，填写本PCB唯一的**批次ID**，点击“加载方案”。先逐项核实硬件适温、安全、急停、线缆、看护和温箱温度预调，完成确认才点“启动自动温补实验”。
5. 本次任务完成且真实WK停车/温箱停止回读已确认后，按厂家温箱程序预调到+85℃附近；第二次选择“**降温 85→−40℃**”，使用**完全相同的PCB、批次ID、IMU量程/ODR、夹具**，再次点击加载、确认并启动。两次任务各有一个`THERM_...`文件夹。
6. 两个任务都为COMPLETED后，在该页点击“**合并本批升温+降温结果 → 生成HTML质量/热滞后/六轴报告**”，选择包含两次 `THERM_...` 的**父目录**。也可以在源码目录执行：

   ```powershell
   py -3 production_cycle_analysis.py "E:\动态倾角仪研发\溫補測試"
   ```

7. 报告会生成到新的 `WK_R4双向温补研究结果_日期时间` 子目录，包含 `双向温补质量分析报告.html`、候选排名CSV、原始两方向差异CSV、轴向符号检查JSON、全量系数与报告JSON。

### 重要：温箱预调

**本版本没有厂家已证实的温控“升降温斜率编程”API。** 为避免从室温向−40℃或+85℃一步跃变，在自动开始前要求**温箱当前PV距第一目标点不超过8℃**；如不满足，须由操作员按照厂家批准的斜坡程序安全预调，**不能**强行修改阈值后让软件下发未知斜率命令。环境、壳体、线缆、PCB的适温必须自行核实。任一硬件报警都应通过物理急停、设备厂家指导的操作处理。

## 2. 产品范围与生产研究方案

- **你的产品指标范围**：−40℃～+85℃。ST官方ASM330LHHX器件范围是−40℃～+105℃；**器件范围不等于整机批准范围**。
- 每次扫描26个**设定点**：−40、−35、…、80、85℃，间隔5℃。
- 其中**14个拟合温度**：−40、−30、−20、−10、0、10、20、30、40、50、60、70、80、85℃。
- **12个独立温度验证点**：−35、−25、…、75℃，用于模型锁定后评价，绝不参与温补/几何模型选型。
- 两次方向各采一次；升温和降温下的同一设定温度记录在**不同文件夹**，防止键覆盖。
- GYRO速率拟合幅值：1、2、5、10、20、30°/s；独立验证：1.5、3.5、7.5、15、25°/s。每点在X/Y/Z方向的既定WK组合姿态做正、反双向速率。**这不是±250°/s满量程验证**。若最终产品需大于±30°/s的角速度性能声明，需另经厂家运动安全审查后扩展动态速率独立验收。
- 两方向总工况**约3608项**（每个拟合温度92项、每个独立验证温度43项，每个方向1804项），每次热浸至少30min；总采集时间可能很长，须预留设备值守和断点续做。

## 3. 温控不是“开头看一次”

- 新温度点：PV初始观察180s、极差≤0.8℃、斜率≤0.15℃/min；有效共同热浸至少1800s；最终PV目标±0.75℃累计180s；芯片温度新鲜采样60s极差≤0.20℃。
- 采样/定位时：基于真实PLC和芯片新帧，持续运行质量看门狗；本R4的运行期软暂停阈值：PV偏差>1.0℃持续60s、严重偏差>1.5℃持续60s需要重新热浸；芯片60s极差>0.30℃持续60s、芯片5min变化斜率>0.10℃/min持续120s会暂停。此软件看门狗**不是硬件超温安全控制器**。
- 每个工况还检查温差≤0.5℃、反馈时间、静态/动态质量和有效帧；严格模式跨同温同类工况芯片温差>0.6℃会有限补测，失败记为缺失而不是通过。温度记录采用每工况有效芯片帧均温，而**不是**设定温度。正式评估必须检查芯片**实际**温区是否覆盖−40～85℃。
- 温箱可达到的PV稳定性以设备实测为准；如果设备无法满足预设阈值，只能报告无法执行或经质量负责人正式重设计试验，不可静默降低后宣称达标。

## 4. 联合反演和温补模型

- 几何候选M0/M1/M2/M3：无修正、外轴等效参考偏移δ、外轴等效轴倾ε、两者联合。仅用拟合温度/拟合姿态估计几何，利用同温独立工况选型，避免动用独立温度验证数据。
- 同时对ACC/GYRO比较**原28个候选**：A0＋T0/T1/T2×B/C/D×1/2/3；额外研究 `T0-SEG2`（在22.5℃有连续分段二次基函数）与`T0-D3_HY`（三次零偏+方向状态）。T1/T2需要同次实验的真实温箱PV逐工况记录，缺失时标为未评估，绝不填补设定值。
- 温补一般形式：`m_raw=F(Tchip,branch)*x_reference+b(Tchip,branch)`；`x_corrected=solve(F,m_raw-b)`。T0以工况实测芯片均温为自变量；D表示完整3×3矩阵可随温度变化；数字1/2/3是多项式次数。
- 先用同温独立姿态选模，再固定候选到独立温度评估。T0-D3并非强制唯一选中，每批次可能选到不同族或分段结构。
- **分段和热滞后不能盲目合并**：正常共享温补曲线优先；升/降温校正后同工况差异RMS超过ACC 2mg或GYRO 0.03°/s则报告阻断。若方向依赖模型获胜，固件必须知道升/降温状态及时间常数后才可实现；目前**不会自动生成可烧录的状态机**。

## 5. 轴符号/六轴对齐——真正的物理边界

- 校正后ACC和GYRO设计上目标同为末端P坐标系，不自动等于PCB/产品坐标系。
- 若检测到ACC前向矩阵`det(F_acc)<0`而GYRO为正，程序会指出符号差异、列出可选代数通道翻转并提供精确不变性验证：`F'=S F, b'=S b, m'=S m ⇒ F'^{-1}(m'-b')=F^{-1}(m-b)`，因此**不能只靠拟合RMSE知道物理上该翻X/Y/Z哪一轴**。不会偷偷翻转并假装已认证。
- 六轴真实共同轴对齐至少需要在已确认的产品PCB坐标上做多轴静态、正反动态和同步`d(g)/dt≈−ω×g`检验。没有这些实物参考时，标定报告一律为**RESEARCH_ONLY_NO_PRODUCTION_RELEASE**。
- 转台等效δ/ε只用于该台设备的离线参考诊断，**通常不写入产品MCU**。产品最终应写入经过独立确认的ACC/GYRO温补系数与公共产品坐标变换，不得用同一块未独立校准的IMU来证明自己的绝对精度。

## 6. 研发验收门槛（建议值，非国家/厂家计量标准）

ACC独立温度向量RMSE≤2mg、模长RMSE≤1mg、重力方向角RMSE≤0.10°；GYRO独立温度向量RMSE≤0.03°/s、零速RMSE≤0.02°/s；两方向校正后同工况差别以ACC 2mg、GYRO 0.03°/s为暂定滞后复核门槛。量产前应由产品负责人用独立计量基准、实际动态响应、寿命/热循环和统计良率重新批准并固化。

## 7. 测试和运行限制

本包使用历史上位机完整源码与厂家DLL。已验证纯计算/静态/旧温补回归测试，但**当前Linux环境没有PySide6、Windows厂家DLL、WK和温箱实机连接**，没有做整机联调；务必先在Windows按厂家方法用假负载/中间温度低风险测试按钮、急停及停机回读，不能第一天就放无人值守全温多循环。

原先常温15点实验无法证明−40～85℃的真实性能；首次真实双向全温采集后才可以输出该温区的有效结果。R4所有输出文件保留原始数据和研究参数，并不自动覆盖旧常温参数或MCU。
