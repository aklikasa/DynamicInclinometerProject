### 为什么只改这两类门槛？

2FDT600WK说明书给出的温箱标称波动度为≤±1℃、温度偏差±2℃、均匀度不大于±2℃。这些不是标定合格标准，但它们说明让这台温箱连续整夜满足±0.1℃是不合理的默认前提。温补依据主要是每条工况的实际芯片温度、采样稳定、转台真实参考和跨温度独立验证。数据明显失稳时必须拒绝该工况。**不能靠把阈值无限提高而保证最后有合格系数。**

## 2. 这次修复的“跑完却没有可用报告”路径

**每次实验结束（包括意外中止）都生成：**

- `thermal_result_readiness.json` —— 按15个温度点的实际计划逐项核对ACC、GYRO独立完成率；指出拟合温度、独立温度和缺失数量。
- `thermal_result_readiness.md` —— 同样的中文人类可读明细。
- `thermal_incomplete_data_report.xlsx` —— 结束时存在缺失工况才生成；即使中止发生前没来得及加入“待补测”列表，也从原计划对照补齐缺失说明。
- `thermal_auto_skip_summary.json` —— 只有自动跳过温度时生成；跳过不代表合格。

**所有工况完整**：继续生成原版 `thermal_calibration_report.xlsx`、ACC/GYRO各自28模型、数学结构、系数、排名、独立验证误差等。报告Excel新增“结果可用性与缺失温度”工作表。

**有工况缺失**：

- 完整传感器仍在 `PARTIAL_ONLY_COMPLETE_SENSORS_RESEARCH/` 独立分析；
- 未完整的传感器也尝试在 `PARTIAL_INCOMPLETE_SENSORS_RESEARCH/` 生成28模型 **研发预览**，并明确标记缺少哪些工况、实际能评估多少模型、独立温度是否有效；
- 若数据不够，不生成虚假的参数：模型状态为 `NOT_EVALUATED`，数学结构及缺失原因仍有报告；
- 模型拟合、可用于研发的候选系数、最终MCU量产参数是三件不同的事，不能互相替代。

**重要限制：** ACC/GYRO完整温度曲线上的28方案不一定都能拟合：部分高阶模型需要至少5个有效拟合温度；T1/T2模型需要可用真实温箱PV；独立验证温度不能用于模型选型；超出实际芯片拟合温区的验证点不能当作有效外推。任何一种条件不满足，必须报告拒绝原因。**没有程序可以保证尚未采到的数据自动产生可信温补系数。**

## 3. 正常结束、自动回25℃与PLC停止

- 全部温度工况结束后，先确认转台两轴真正停稳。
- 按勾选项可自动回25℃，**最多等待60分钟**；若超时且PV在0～45℃，会记录“没有回到25℃”，转入温箱停止定值运行请求与回读确认；若PV超出可审计停机区间则作为异常，要求现场按厂家流程处理。
- 向PLC发停止定值运行并检查新鲜状态。**没有新的停止反馈就标“停止未确认”**；这不等于切断温箱总电源，也不构成可无人看守的实机安全认证。
- PLC报警、SP被外部修改、通讯失联、转台真实停车未确认、IMU数据失联等均属于真实设备异常，不会被当作普通质量问题跳过。

## 4. 本次建议的运行方法

1. 解压到**新目录**，不要覆盖正在运行或保存了旧检查点的工程。
2. 选 **PLC自动控温 / 研发连续温补V3**，不要选“快速流程联调模式”。
3. 若继续使用上次的15温度规划，拟合温度输入 `5,10,15,20,25,30,35,40`，独立验证温度输入 `7.5,12.5,17.5,22.5,27.5,32.5,37.5`；以界面显示的真实实验计划为准。
4. GYRO低速优先拟合 `1,2,3,5,10,20,30°/s`，验证 `1.5,2.5,4,7.5,15,25°/s`，原速度列表及自定义功能保留。
5. 推荐温漂暂停上限先保持5次、单温度稳定等待上限先保持120分钟。低温5℃阶段很不稳定时，软件可以自动跳温，但跳温会损失独立验证或拟合数据。
6. 新实验起始必须先由现场人员验证温箱设温/SP/PV、转台内外轴正反转/停车、PLC停止命令与回读、软件急停与恢复。**离线测试不等于无人值守设备安全认证。**
7. 完成后先读 `thermal_result_readiness.md`；只有数据足够且温度独立验证误差满足项目目标，才考虑采用温补候选。
