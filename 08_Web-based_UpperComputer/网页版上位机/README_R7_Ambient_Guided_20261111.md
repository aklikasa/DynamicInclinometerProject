# WK IMU R7 常温标定 Web 迁移：真实逐工况采样版

本更新基于现有 **R7 白色网页版 + 2TD600 双轴手动控制版**。不是模拟数据，不需要启动 PySide6 桌面 UI。

## 本版已接入（实时硬件需现场验证）

- 新增“2TD600 常温标定转台”页面底部的 **常温 IMU · 逐工况真实采集与 A/B/C 校验**。
- 从原 `production_calibration.py` 加载 ACC **12 拟合 + 12 独立验证**，GYRO **32 个零偏/正反向速率工况**。
- 使用原 PCB 的 **唯一串口轮询线程**回调，获取每帧 16 个原始换算样本。没有独立启动第二个 COM、没有模拟采样。
- 取得 2TD600 实际角度、速度和反馈时间：超时、不在位置、静态不静止、动态速率不稳定、量程/ODR 变化均拒绝采样。
- 采用 R7 原始 `frame_average_sanitized()` 和 `robust_segment()` 做 MAD、温度、抖动与有效帧质量检验；失败不跳过工况，可重新采样。
- 全部工况完成后，使用 R7 原始 `compare_models()`/`save_model_comparison()` 做 A/B/C 模型的**拟合与独立验证**，保存 JSON、CSV、Excel（仅候选结果，不写 PCB/MCU 系数）。
- 实验会话文件、逐工况数据和事件日志位于 `TiltSensorCalibration/native_web_data/ambient_guided_runs/`；可以网页下载。

## 当前不能宣称已完成的能力

- **没有实现转台的自动连续逐姿态驱动与 GYRO 速率自动切换**。本版是 **人工按工况定位 + Web 真实采样/质控/拟合**，不是无人值守全自动标定。
- R7 原 Qt 界面 `_auto_task_tick()` 的全部机械找零、调度、失联自动停车和自动重试状态机仍需进一步独立迁移及真机验收。
- 暂未增加独立的“速率模式”控制按钮：GYRO 速率工况需通过已验证的厂家控制器建立稳定正/反向角速率，不能只输入位置运动速度替代真实匀速工况。
- 不支持重启后自动恢复未完成的采样会话。已完成部分的 JSON 数据和事件日志会保留，但重启需新建任务，避免恢复到错误物理姿态。
- **厂商 2TD-600 最高额定 60°/s，不代表标定工艺可直接用 60°/s**。当前仍保留 R7 的 10°/s 工艺上限；在 2TD600 负载与工装条件下必须遵守厂商的轴间互锁与急停要求。
- 软件停车、串口断开、伺服失能、控制柜急停是不同动作。**网页不能代替实体硬件急停**。

## 现场使用顺序

1. 关闭当前网页后端，确保转台停稳；将补丁全部解压到已经能连接 PCB 与 2TD600 的网页工程目录。
2. 双击 `Apply_R7_Ambient_Guided.cmd`，结束后启动 `Start_R7_Web_Win11.cmd`，浏览器按 `Ctrl+F5`。
3. 连接真实 PCB 和 2TD600，并确认 PCB UID、角度、速度、使能状态和现场独立硬件急停；不要在转台运动区域逗留。
4. 进入 **2TD600 常温标定转台** → 底部“常温 IMU · 逐工况真实采集”，输入 PCB 编号、重力符号并勾选现场安全确认。
5. 点击 **创建 ACC 24 姿态任务** 或 **创建 GYRO 32 工况任务**，页面会显示目标姿态与转速。创建任务**不会**驱动转台。
6. 使用原来单独的转台手动控制/厂家控制器定位到当前姿态，等待静止或稳速；再点 **开始当前工况采样**。
7. 等待工况所需的真实时间，点 **完成采样并质量判定**。失败时会显示原因，修正后重新采当前步骤，不会自动跳过。
8. 全部工况完成后下载 **model_comparison_acc/gyro.json、.csv、.xlsx**，同时保留 `measurements.json`、`session.json`、`events.jsonl`。

## 验收范围

已经在无硬件环境完成 **65 项离线测试**、HTTP 接口/拒绝无设备测试、网页静态布局检查。
**未执行 Win11 + 实际 2TD600/PCB 的现场逐工况标定，未验证全 24/32 工况上的拟合精度**。真实机台的运动控制与数据采样必须在现场验证，报告自动生成不等于产品验收放行。
