# IMU 自动标定工作台第三版：自动流程与算法说明

## 本版实现范围

本版将三个任务从“只生成计划”改为真正的自动任务状态机：

1. 加速度计 36 位置自动标定；
2. 陀螺仪静止零偏 + 多姿态、正反向、多速率自动标定；
3. 六轴坐标对齐与验证，并生成组合参数文件。

IMU 页面不再提供转台端口选择或手动运动按钮。它通过 `FormTurntableCtrl` 使用原转台页面的共享连接和 `turntableComm`，避免两套独立连接。

## 启动前条件

- 在“转台”页面连接并使能 2TD600，确认内外轴位置/速度反馈有效。
- 在“倾角仪校准”页面打开 IMU 串口，确认数据持续更新。
- 停止“倾角仪校准”原有 CSV 记录；本页会建立独立实验包。
- 勾选安全确认：转台安装牢固、基座水平、轴系模型已核实、线缆无缠绕、运动范围无障碍、硬件急停可用。
- 首次执行必须低速、无人靠近运动范围，先验证实际方向与停车行为。

## 轴系参考模型

界面提供两种正交水平轴模型：

- `outer_x_inner_y`: `R = Rx(outer) @ Ry(inner)`
- `outer_y_inner_x`: `R = Ry(outer) @ Rx(inner)`

界面还要求选择基座重力参考方向（+Z 向上或 +Z 向下）。其中 `R` 把平台坐标向量变换到转台基座坐标。静止比力参考为 `R.T @ [0, 0, gravity_sign] g`。陀螺仪参考角速度由内外轴实际角速度、实际位置及同一旋转模型计算，再表达在平台坐标系 P 中。

**这不是从软件里猜出来的转台机械定义。** 使用前必须根据转台结构/说明书确认内外轴正方向、轴序、零位和基座水平情况。若模型与实机不一致，结果文件虽可能生成，但不得用于产品放行。

## 加速度计任务

- 36 个位置为内、外轴各 6 个角度点的网格。
- 每个位置：绝对位置运动 -> 等待到位且速度接近零 -> 稳定等待 -> 采样。
- 每个姿态保存采样帧均值、实际反馈角度、参考重力向量。
- 用 `raw_acc = A * gravity_platform + bias` 拟合三轴线性模型，输出 `inverse(A)` 作为 raw-to-platform 校正矩阵。
- 输出矩阵条件数、向量 RMSE、最大向量误差以及每个姿态的测量值。

## 陀螺仪任务

- 首先静止采集零速样本。
- 内轴在多个外轴姿态、外轴在多个内轴姿态下，分别执行 ±1、±2、±5 °/s 速率。
- 运动期间使用实际位置和实际角速度反馈计算平台坐标系参考角速度；使用线性最小二乘拟合 `raw_gyro = A * omega_platform + bias`。
- 输出零偏、raw-to-platform 矩阵、矩阵条件数、向量 RMSE 和最大误差。
- 任一步骤出现连接/数据中断、状态故障、限位、到位超时、速率未稳定或停车超时，任务进入中止流程并向两轴发送停车命令。

## 六轴对齐与验证

- 读取根目录的 `accel_calibration.json` 与 `gyro_calibration.json`，并要求两者轴系模型一致。
- 执行 6 个静态验证姿态和 6 个低速旋转验证工况。
- 通过校正矩阵的极分解提取旋转分量，计算 gyro corrected frame 到 accel corrected frame 的相对旋转矩阵和 ZYX 欧拉角。
- 用验证采样计算加速度向量 RMSE、陀螺仪角速度 RMSE。
- 输出 `alignment.json` 与 `imu_calibration_final.json`。

## 输出文件

在用户选择的根目录下：

- `accel_calibration.json`：最近一次加速度计候选标定结果；
- `gyro_calibration.json`：最近一次陀螺仪候选标定结果；
- `alignment.json`：最近一次坐标对齐与验证结果；
- `imu_calibration_final.json`：组合参数候选文件。

每次任务还会建立独立运行目录，包含：

- `imu_raw.csv`
- `turntable_feedback.csv`
- `events.csv`
- `step_markers.csv`
- `manifest.json`
- 本次任务对应的标定结果 JSON；对齐任务还包含组合参数文件。

根目录中的固定名称文件是“最近一次结果”，会被后续同类型任务更新；每次运行目录内的结果副本保留历史记录。

## 算法和安全边界

- 矩阵拟合是完整三轴仿射模型，不是旧版仅拟合三个轴向椭球半径的简化方法。
- 陀螺仪拟合使用转台反馈作为参考，不能消除转台自身角速度误差、反馈延迟、IMU/转台时间不同步或结构振动。
- 结果状态标记为 `computed_needs_engineering_validation`。这表示软件完成了计算，并不等于达到角分精度或通过计量验收。
- 本环境只能做 Python 语法检查、UI XML 检查和合成数据数学测试；不能替代 Windows + PySide6 + 厂商 DLL + 实机联调。
- 软件停车不能代替硬件急停。若停车后反馈仍非零或通讯失联，应立即按现场规程使用硬件急停。
