# 温补运行期温漂误暂停、过早恢复修复（2026-11-06）

**针对实际运行 `THERM_20261106_142943` 日志开发；此为软件离线验证版本，真实PLC、温箱、WK转台未在本环境实机验证。**

## 实测问题

- 20℃热浸3600秒及最后PV±0.10℃/300秒、芯片60秒波动≤0.20℃均通过后，开始ACC工况；但是定位运动时出现短时芯片温度波动/斜率接近±0.05℃/min，引发重复停车。
- 16:22:51→16:22:53、16:23:35→16:23:38 等几秒内恢复，说明恢复判据误用停车前120秒历史。重复启停不适合温箱内长期实验。

## 代码修复

1. `thermal_runtime_guard.py`：正式开始前温度门槛**不变**；针对*运动/标定阶段*的软暂停采用有持续时间的研究性门槛：
   - 温箱PV偏离目标**>0.50℃连续30秒**，才软暂停（旧为>0.30℃连续15秒）。
   - 芯片60秒极差**>0.40℃连续30秒**，才软暂停（旧为>0.20℃直接暂停）。
   - 芯片5分钟线性斜率绝对值**>0.10℃/min连续60秒**，才软暂停（旧为>0.05℃/min直接暂停）。
   - **PV偏差>1.0℃持续30秒**仍触发重新完整热浸。PLC报警、通信失效、WK失控仍执行原有故障安全中止。
2. `form/form_thermal_compensation.py`：定位运动的`position/wait_position`阶段不因普通芯片软质量报警中途重复停车；达到安全采样前边界后再处理（严重温度漂移/PLC硬故障不豁免）。
3. 每次WK实际停车并确认1#双轴静止之后才调用 `begin_recovery()`：清空**仅用于恢复验证**的旧PV/芯片观察历史并重新计时；恢复前必须积累连续且新鲜的PV+芯片数据（PV目标±0.30℃、芯片60秒极差≤0.20℃）。缺失反馈、不足120秒或跨窗口跳点不能恢复。
4. 同一温度点第1/2/3/4次温漂软暂停自动恢复需要的**停车后**观察时长依次为120/180/300/600秒。第5次进入 **`thermal_operator_hold` 静止人工等待**，禁止继续自动驱动转台。新增按钮：`温漂多次暂停：现场确认安全后重新等待稳定...`，仅在人工静止等待时可用，必须核对WK真实停车、PLC正常，确认后重新累计300秒，不跳过恢复检查。
5. 暂停期间当前工况不提交。已合格工况保留并逐项存档。已有**单工况温度极差≤0.50℃**、**同组芯片均温跨度≤0.60℃**及其他ACC/GYRO、WK速度质量限值**全部不变**；待补测、断点续做、拟合/验证温度与拟合/验证速率自由配置、28套模型选择不变。
6. 新实验的 `experiment_config.json` 额外记录 `runtime_temperature_guard_policy`；旧实验续做时原始不可变配置保持原样，新的运行期保护版本/门槛记录在`temperature_measurements.json`事件中，便于追溯，不强行混改旧的正式标定参数。

> 运行期软暂停判据不等于合格数据判据。新的阈值用于减少温箱控制波动/转台姿态变化引起的频繁停启，而不是放宽正式标定数据有效性。工业使用必须依据独立温度与精度验证确认这些默认值是否合适。
