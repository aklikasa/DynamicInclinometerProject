# WK六轴IMU温补上位机 R10 · 完整工程使用说明（请优先阅读）

版本来源：用户提供的 R9.1 完整工程 `WK_IMUE7_.zip`；本版本只修改温补界面的可配置质量门槛与自动温补状态机的启动/停机完整性。其余标定、转台几何参考模型、28候选模型和设备DLL均从上传工程保留。

## 一、先说最终修复了什么

1. **修复界面启动时 `wk_mean_error` 报错**：原代码先访问 `wk_mean_error / wk_slope_delta / wk_position_residual`，再创建这些控件；现在先创建后设置无工程人为上限。增加创建顺序静态回归测试。
2. **PLC设温回读状态不会卡死**：保留R9.1已实现的 `verify_plc_sp`，必须在写目标SP后收到新鲜SP回读、定值模式、启动、运行状态，才进入初步到温。等待90秒仍无法确认时清楚报错、受控中止，不绕过硬件反馈。
3. **PLC定值停止命令失败/90秒无新鲜停止回读绝不标成 `COMPLETED`**：实验状态变 `INCOMPLETE`，保存所有数据与断点，不自动接下一趟，不生成误导性的正式完整28模型结论。WK实际停车也必须确认。停止命令并非断电；温箱异常务必现场处置。
4. **温差超过组阈值时立即中止**：保留已接受工况、均温与原始帧；启动受控停车后，不再从旧代码错误地继续推进下一温度。
5. **生产可调质量阈值生效顺序修复**：先去除原 Qt 控件的人工数值上限，再加载默认值，防止原本的2.5℃/min被旧上限截成2.0℃/min。切换“严格恒温”也不会因缺少运行阈值字典而报错；旧严格运行的实际默认数值保持不变。
6. **新增“芯片温度与PV最大允许差”质量参数**：默认10℃，可以自设，不再暗藏在采样入口。人工到温的固定±2℃也改用初步PV偏差参数。部分温度阶段原本写死“等待超过6小时”的质量条件改用本次设置的“单温度累计等待上限”。
7. **加载生产温度计划不再自动切换温度质量模式**，防止重新加载采样计划时意外覆盖手动阈值。新窗口默认进入“生产自适应”；如果你主动切换质量模式，界面会加载对应模式建议值，需要重新核查。
8. 原“最低温/最高温/循环次数”、直接目标SP、每趟独立目录、逐工况均温、真实PLC/WK保护、28候选模型、等效转台几何M0～M3、原始帧存档、离线回溯算法均保留。

> 注意：本软件用于研发采集与拟合，不构成计量认证、工业安全控制器替代品或自动放行系统。本次环境没有Windows真实WK/PLC/IMU设备与PySide6窗口运行条件，**不能声称已经现场联调或保证所有工况绝不出错**。首次使用请现场值守，仅在机械安全、温箱厂商允许、急停可靠且可人工确认停机时运行。

## 二、开机操作（推荐正式PLC模式）

解压完整ZIP到新的单独文件夹。双击根目录的 `双击这里_启动R10上位机.bat`；也可以进入 `TiltSensorCalibration` 运行 `START_WORKSTATION.bat` 或 `python main.py`。

在“IMU自动温补”页按顺序：

1. 连接IMU、WK转台和PLC温箱，核对设备编号、ACC/GYRO量程/ODR、转台零位与旋转轴方向；现场检查固定、线缆、滑环、门禁、急停与停车反馈。
2. 选择“R8一键N次升温+降温”（该菜单名沿用，但运行的是R10修订逻辑）；填写**最低温、最高温、完整循环次数**。例如最低−20℃、最高60℃、2次循环，共四趟：升温、降温、升温、降温；每趟17个5℃采样温度点，四个独立`THERM_...`目录。
3. 在**温度质量模式**选择“生产自适应”（窗口初始默认）。按你温箱的真实能力输入所有阈值；建议先确认初步到温、热浸、最终PV、芯片窗口、运行暂停与恢复六块配置。模式不同，默认值不同；**不应把软件建议值当作设备承诺能力**。
4. 点击“加载所选温区/5℃采样方案”；它只加载温度及GYRO速率计划，不应重置你已调整的温度质量阈值。核对速率、目标温度、质量模式和批次ID。
5. 按现场要求完成安全确认后开始。每次写PLC目标SP后需等待新鲜回读与状态确认；没确认不能驱动WK开始姿态采集。
6. 运行中查看“当前阶段”和PLC实时PV/SP：若未进入下一阶段，定位下方表格中对应质量条件。温箱温度已接近SP不代表所有极差/斜率/时间条件合格；有问题应检查实时读数及原始记录，**不要盲目取消设备保护**。
7. 所有本温度工况完成才去下个温度；每趟结束必须先WK实际停车，再PLC停止请求并收到新鲜“已停止”回读。若失败，标记`INCOMPLETE`、保留数据、禁止自动接续另一趟。
8. 全部循环完成以后才做合并报告；离线研究报告不代表自动生产放行。旧版本任务跨版本直接续做可能因冻结配置不同不兼容，先备份整份目录，**不要覆盖旧记录或强行续接旧检查点**。

## 三、整套温补状态机：什么时候才进入所谓“热平衡”？

**顺序：**

`next_temperature（WK停车） → 请求PLC定值目标SP → verify_plc_sp（SP/模式/启动/运行确认） → wait_plc（初步到温观察） → thermal_soak（有效热浸累计） → final_stability（最终PV+芯片稳定） → position（逐姿态定位） → settle（停车静置） → sample（ACC/GYRO采集） → 校验与必要补测 → 下一温度 → 可选回25℃ → WK真实停车 → PLC停止及回读 → 完成/不完整`。

这是一条**软件准入链**，不是证明材料内部每个位置完全同温的热学证书。热浸只在PV处于允许范围并有新鲜读数时增加有效累计时间；出范围暂停累计，恢复后继续（不是必须连续900秒）。等待热浸时WK不旋转。热浸结束并不自动采样：最终PV和芯片准入须再同时满足；生产自适应模式还要有足够新鲜数据计算芯片约5分钟线性趋势。

### 1. PLC设温与SP回读

- `SP` = 温箱目标设定值，`PV` = 温箱实际测得值，`T_chip` = IMU芯片自身的温度计读数。三者**不是同一个温度**。
- 设目标−20℃时，软件直接写目标SP，不在软件层生成中间SP阶梯。PLC/温箱自己的升降温和硬安全保护仍按设备控制器工作。
- 新鲜SP回读需与目标约±0.2℃内一致，并确认定值模式、已启动和运行中；相关字段读数不能过期或来自写SP之前。90秒失败：保留数据并中止。不允许把“PV已到温”代替“PLC启动成功”。

### 2. 初步到温稳定（`wait_plc`）

要同时满足三类温度条件加时间：

| 设置项 | 含义 | 典型使用示例 |
|---|---|---|
| 初步PV允许偏差 | 允许PV离SP有多远，`abs(PV−SP) ≤ 偏差` | SP−20℃、允许±1.5℃，即PV须在−21.5到−18.5℃ |
| 初步观察时间 | 连续处于允许带内，并获得足够新的PLC采样的最短时间 | 120秒 |
| 初步PV极差上限 | 该观察窗内 `max(PV)−min(PV)` 可多大 | 1.85℃ |
| 初步PV斜率上限 | 观察窗对PV随时间进行线性拟合，绝对斜率最大多少 | 0.460℃/min |

PV离开初步允许带时，会清空该阶段观察窗口重新统计。即使当前PV=−19.5℃，**只满足偏差不等于已经通过极差、斜率和120秒观察**。

### 3. 共同热浸（`thermal_soak`）

| 设置项 | 含义 |
|---|---|
| 热浸时长（界面“保温/热平衡时长”） | 累计 **有效** 秒数；900秒=15分钟 |
| 热浸PV允许偏差 | 只有 `abs(PV−SP)` 处在这个范围内，且PLC PV反馈新鲜时，才继续增加累计时间 |

例如SP−20℃、热浸±2.2℃，温箱PV在−22.2～−17.8℃、读数新鲜时有效累计。PV越界不删除之前已累计的时间，但不会继续计时。芯片温度全程记录；如果芯片尚未稳定，后续最终准入继续等待。

### 4. 最终PV + 芯片稳定（`final_stability`）

| 设置项 | 含义 |
|---|---|
| 最终PV允许偏差 | 连续检查 `abs(PV−SP)`，不再固定±0.10℃；例：±2.95℃ |
| 最终PV稳定时间 | 至少连续满足最终PV偏差的窗口，例：120秒 |
| 准入芯片60秒极差 | `max(T_chip)−min(T_chip)` 在最近60秒内的最大跨度，默认建议2℃，界面自定 |
| 准入芯片5分钟斜率 | 芯片温度最近约5分钟数据的线性趋势绝对值上限，默认建议2℃/min，界面自定 |
| 芯片与PV最大允许差 | `abs(T_chip−PV)` 的允许差，默认10℃，现在也可设置；防止隐藏门槛卡住 |

5分钟斜率必须先收集足够真实新帧，不能因为最后60秒很平稳就跳过趋势检查。这里的“PV在±2℃内”和“芯片60秒极差≤2℃”**是两个不同的条件**；它们也不同于12姿态之间的均温跨度。

### 5. WK姿态与六轴采样

- 初步到温、热浸、最终稳定阶段WK保持停车。开始测量后，逐姿态转到指定角度、确认编码器位置/真实停止、静置，再用有效帧采样ACC和GYRO。对角速度工况还要检查真实转向、稳速、编码器反馈新鲜度、采样窗口及停车。
- **每一个工况的温度自变量 = 此工况全部通过筛选的有效帧芯片温度的算术平均值**。不是SP，也不是温箱PV。逐帧原始文件、该工况温度极小/极大/跨度都存档，可离线重新处理。
- 一个温度的ACC拟合姿态仍要完整12姿态，联合识别一套温度矩阵，不会拆成12套独立校准矩阵。跨姿态芯片均温跨度的**停车阈值**默认2℃，可调整或关闭这个**采集质量**停车门槛；超过时先保存，再受控中止，不会自动删掉整组或跳下温度。
- ACC/GYRO各保留28模型评估（A0 + T0/T1/T2 × B/C/D × 一至三次多项式），保留转台等效几何M0～M3候选及共用几何参考关系；**这些并非转台机械误差的计量认证**。

## 四、运行途中温漂暂停、重新热浸与恢复阈值

| 运行期输入 | 作用/判定 |
|---|---|
| 运行PV暂停偏差 | `abs(PV−目标SP)` 超过此值，并持续“连续超过时间”，进入温度质量停车等待；默认自动跟随关闭，因此可以独立输入 |
| 运行PV暂停持续时间 | 超出暂停偏差要持续多久才算暂停，过滤瞬时抖动 |
| 重新热浸PV偏差 | PV长时间偏离到更高幅度时，不只是暂停当前工况，还会重新累计本温度的热浸时间 |
| 重新热浸持续时间 | 上述较大偏差持续多久才触发重新热浸 |
| 运行芯片60秒极差上限 | 运行期间芯片最近60秒温度的最大跨度；超过一定持续时间触发质量暂停 |
| 运行芯片5分钟斜率上限 | 运行期间芯片温度变化速度；达到持续超限条件进入暂停 |
| 恢复时PV最大偏差 | WK停车后，PV必须重新处在较窄范围，才算恢复稳定 |
| 恢复时芯片60秒极差与5分钟斜率 | 需用停车后的新鲜温度数据重新判定，不能使用停车前旧窗口 |
| 停车后连续恢复合格时间（秒） | 每次因温漂停车后，PV/芯片新鲜读数连续满足恢复条件的最短观察时间，可在界面设置；默认300秒，不再暗中根据暂停次数强制300/600秒 |
| 单温度暂停次数上限 | 达到预设上限不跳温，保留数据、记录未完成并受控中止 |
| 单温度总等待上限、恢复等待上限 | 不能无限等待质量条件；超时标记`INCOMPLETE`并按安全流程停车 |

这些**采样质量参数不设置任意工程数值上限**；但输入必须是有限/非负的有效数值，并遵守基本逻辑关系：恢复PV偏差应小于暂停偏差，重新热浸PV偏差应大于暂停偏差，恢复芯片跨度/斜率不大于运行期对应门槛。宽松参数可能让热滞后数据被当作“合格”，**记录完整不代表精度足够**。PLC硬故障报警、通信超时、传感器超出物理有效范围和WK运动/停车保护不会因提高质量阈值而失效。

## 五、结束、状态与结果

1. 全部温度工况测完后，若选择回常温，先执行可选的回25℃流程；若到温等待超时，要明确记录“未完成回温”，不得宣称已稳定回温。
2. WK发停车命令后，须有真实反馈证明两轴停止；不能把“请求已发送”等同停车。
3. PLC发停止定值运行命令后，必须获得写命令**之后的新鲜状态**证明“定值启动=False 且运行=False”，才能把PLC自动模式的这趟实验标成 `COMPLETED`。90秒失败会保存原始数据、`INCOMPLETE`、停机未确认提示，禁止接续下一趟。
4. `INCOMPLETE` 的数据允许离线研究，但不是完整模型放行。每趟应有 `experiment_config.json`、`temperature_measurements.json`、`imu_full_frames.jsonl`、WK反馈记录及审计报告。多次循环各趟独立目录，不覆盖。
5. 只在真实完整并停机确认后开始生产循环的下一趟；全部2N趟完整后才合并多循环模型、热滞后和六轴验证。离线28模型拟合可能因数据缺失、条件数、独立验证失败而标记不可计算/不放行，不应伪称28套全成功。

## 六、测试与重要边界

- R10新增的8项无硬件回归测试覆盖GUI自属性初始化顺序、PLC停止写入失败、PLC停止读回超时、资料完整但停机未确认、跨姿态温差受控中止后不前进、等待上限不被隐藏6小时限制以及严格/研发/生产三套运行阈值完整性。
- 保留R9.1原有PLC SP新鲜回读测试、R8多循环和逐工况均温测试、既有28模型和几何校验测试。
- 原工程工具目录仍含两项旧版静态检查失败（旧界面“回零中”字符串、旧核心文件哈希，与本轮代码修复无关）。`tests_r6`还有一项测试仍按“中间SP步进”旧协议期望，R7/R8/R9/R10已改为直接目标SP，故不适用于现工艺。不应删除或改写这些测试让它们假装通过。
- 不可用的验证：本环境未安装Windows版PySide6及WK/PLC/IMU真实硬件，**GUI真实窗口启动、实际PLC回读时序、断电/急停可靠性、冷热设备长周期极端实验**均须你现场有值守测试。源码编译和离线模拟无法替代实机安全验收。

**重要：不要在温箱正在制冷/加热、WK仍有运动时直接关闭电脑、拔PLC线或强制断电。先按设备厂家安全停机流程确认状态，再处理工程版本。**
