# R5 WK双轴转台 / ASM330LHHX 六轴温补生产研究版 —— 先读我

> **运行状态：现场工程研究验证版，不是已获得计量认证的生产放行系统。** 代码离线回归与合成数据端到端运行通过，但本交付环境没有Windows/PySide6、WK转台和PLC实机，所有实际转台/温箱命令、断电恢复与极限温度必须先在有人监护下逐段联调。本程序不自动写入/烧录MCU。

## 一、最简单启动方法

1. **完整解压 ZIP**，不要单独拖出 main.py，DLL 与模块必须留在原相对位置。
2. Windows 64位、兼容的 Python 和原厂驱动/Snap7环境按原R4方法安装。在 `TiltSensorCalibration` 文件夹内双击 `运行R5上位机.bat`（最外层也有 `双击这里_启动R5上位机.bat`）。启动程序仍是 `main.py`。
3. 打开 **「IMU 自动温补」**，在 **「扫描任务」** 选择默认的 **「R5 一次启动自动升温＋降温」**，在 **「最终曲线策略」** 保留 **「统一一条曲线」**。
4. 输入**PCB序列号**、批次ID（只能使用中文/英文字母、数字、下划线、横线或点）、数据父文件夹。点击 **「加载−40～85℃/5℃采样方案与保守GYRO速率」**。
5. 确认原上位机设备连接及全部安全项，确认温箱/PCB/线缆/滑环/急停/值守已在目标温度范围安全验证。选PLC自动温控、严格恒温，禁止快速跳热浸；确保初始温箱/芯片已按设备条件预冷至−40℃附近。
6. 点击原有 **「开始」**。软件先完成上升段 `−40,−35,...,+85℃`；每一温度点按**实时PV+芯片温度稳定**门控，ACC静态24姿态、GYRO正反转多个工况按照原有程序进行，逐帧保存。
7. 升温段成功结束后，只有 **WK真实停车确认 + PLC新鲜停止回读 + 工况全完成** 同时满足，才允许自动接续降温段 `+85,+80,...,−40℃`。降温末尾按原勾选可回室温并安全停止PLC温控定值运行。两段记录分别保存在同一父目录下两个不同的 `THERM_*` 文件夹，绝不复用同温度检查点覆盖前一段。
8. 两段真实完整结束后自动分析并在浏览器打开 **《双向温补质量分析报告.html》**。也可选择 **「合并本批升温+降温结果」** 手动重新分析；结果目录名以 `WK_R5双向温补研究结果_` 开头。

**启动前强制提醒：** 软件不能替代硬件急停、独立温度保护、厂家转台限位或温箱过热保护；请先逐项验证停车指令、伺服状态、PLC回读、加减速、热浸停机、通信故障安全策略，再安排长时间全温实验。错误/缺失工况会阻止自动接续和正式结论。

## 二、温度、速度与统一曲线

- 温箱**设定** `−40～+85℃`，5℃一步，共26点；上升及下降各一趟。**实际芯片温度**必须在报告中单独检查，温箱设到−40℃不等于芯片已到−40℃。
- 14个拟合温度：`−40, −30, −20, −10, 0, 10, 20, 30, 40, 50, 60, 70, 80, 85℃`；其余12个中间温度只做**独立跨温验证**。每个拟合温度中的独立工况也不用于候选模型拟合。
- GYRO正反向拟合速率 `1,2,5,10,20,30°/s`；独立验证 `1.5,3.5,7.5,15,25°/s`，均要通过WK安全/加速度/线缆等实际确认。它们是研发验证方案，不能代表±250°/s全部量程覆盖。
- 默认单曲线：对升温、降温两趟的训练记录**联合拟合唯一** `F_acc(T),b_acc(T),F_gyro(T),b_gyro(T)`。ACC和GYRO各有一套标定矩阵及偏置，但在研究模型中输出到同一个WK末端坐标定义；**不是两条升降温补偿曲线**。
- 比较原28个温度输入/结构候选，另加连续二次、连续三次分段候选（例如在0℃、25℃处连接）；分段候选至少函数值与一阶导数连续，避免分界跳变。单曲线选模不允许选择含升降方向变量的 `T0-D3_HY`，该模型只供研究。无足够真实PV时T1/T2候选明确不评价。
- 升温和降温必须**分别**在独立验证温度上验收；同温升降温差过大，即使平均RMSE看起来好，仍须标记**单一静态温度曲线不满足要求**。不得静默改用两条曲线，更不会自动烧录参数。
- 拟合与验证均用芯片实际测得温度，不用温箱设定值充当温补自变量。报告内所有门槛为**研发建议值**，不是生产计量认证值。

## 三、R5新增独立温度斜坡法

1. 完成稳态双向扫描及报告后，保证**PCB牢固固定，WK真实静止**。
2. 用**经设备厂家确认的温箱斜坡程序**实现温度持续上升与下降；建议先低速0.5℃/min，再测试1℃/min，确认温箱/PCB安全。**R5仅记录，不自动向PLC下发未经验证的斜坡速率命令。**
3. 在同一 `PCB编号 / 批次ID / 数据父文件夹` 下勾选斜坡监护确认，点 **「开始静止斜坡记录」**；同时读取IMU实时六轴、芯片温度、PLC PV、WK停车状态，并生成 `R5_RAMP_*.csv`。同一连续记录中需要包含真实芯片温度的**两个方向**各至少10℃有效温度跨度，且原始数据新鲜。记录期间不得让WK运动。
4. 斜坡结束点击**「结束斜坡记录」**，再点 **「合并本批升温+降温结果」** 重新出报告；**只有采集到真实斜坡数据时报告才会计算斜坡补偿前/后残差**。缺少时标 `NOT_EVALUATED`，不视为通过。
5. 斜坡法的ACC方向基准来自相对固定姿态，不能替代独立绝对水平和外部角度计量；GYRO检查静止零速漂移。

## 四、六轴真实对齐测试

R5离线分析尝试读取每个方向的 `imu_full_frames.jsonl`，只选择**独立验证温度和独立转速工况**中可用的同步六轴真实帧（非人工数据）。检查标定后的重力单位向量运动学关系：

\[d\mathbf g/dt+\boldsymbol\omega\times\mathbf g\approx0\]

至少两个足以激发重力方向变化的不同旋转轴、足够帧数和时间戳；数据缺失、轴激发不足、符号或坐标不一致时，标记 `NOT_EVALUATED` / 不通过。**这只能证明部分动态一致性，不能证明PCB绝对X/Y/Z方向和真实零位已通过独立计量验收。** 一般还需要单独硬件坐标基准、绕重力轴工况与已知角速度量值复核。

## 五、HTML报告与数据保存

联合分析产生：

- `双向温补质量分析报告.html`：实验身份、门槛与放行阻断项、升降温双方向跨温独立验证、分段候选、热滞后、斜坡验证、六轴运动学、坐标轴手性风险、转台等效M0–M3几何模型、补偿矩阵及追溯信息；内嵌SVG曲线可以离线打开。
- `模型评分.csv` / `升降温独立验证.csv` / `升降温原始差异.csv`。
- `全量研究结果_不得直接烧录.json`、`统一温补研究参数_未经生产批准.json`、`原始六轴符号校验说明.json`。
- 完整原始IMU日志、转台编码器和实验设置保留在两个 `THERM_*` 文件夹中；循环状态保存在 `R5_CYCLE_<批次ID>.json`，失败和未完成均保留追溯状态。

报告的 `RESEARCH_ONLY_NO_PRODUCTION_RELEASE` 是刻意设计：**完整的软件研究评估 ≠ 自动获得厂家生产放行资格**。几何参数是等效反演，不修改转台厂家零位；最终运行参数只有独立批准后才能转成固件格式，当前R5不会直接写入。
