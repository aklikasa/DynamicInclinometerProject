# IMU 标定实验页（第一版）使用说明

## 版本目标

本版本在现有倾角仪校准工程中增加“IMU 标定”页面，优先验证可追溯的数据采集和转台单步控制，不执行整套自动运动计划，也不在界面内自动拟合标定参数。

## 运行前

1. 在 Windows、项目原有 Python 环境中运行 `main.py`；保持当前工作目录为项目根目录，以便加载原有 DLL 和 `config.xml`。
2. 先在“倾角仪校准”页面打开 IMU 串口，确认有有效数据。
3. 在“IMU 标定”页面刷新 COM 端口，选择 2TD600 的实际端口并连接；连接逻辑复用原来的转台控制模块。
4. 首次测试请卸下载荷风险、线缆缠绕风险和周边障碍；先低速测试。软件停止按钮不是硬件急停。

## 页面功能

- **连接转台**：刷新可用串口；使用选中的 COM 端口连接 2TD600。当前页面的单步运动控制只支持 2TD600。
- **单步速率控制**：选择内轴/外轴，设置目标速率和加速度，勾选安全确认后发送一次速率运动指令；可停止所选轴或停止两轴。第一版软件速率限幅为 ±10°/s，默认 1°/s。
- **开始实验记录**：在保存根目录下创建唯一实验文件夹，不覆盖已存在文件夹。要求 IMU 已打开并收到有效数据。
- **记录工况标记**：把人工定义的工况编号、备注、当前转台反馈和 IMU 帧计数写入 `step_markers.csv`。
- **停止记录**：停止队列入队、排空已缓存数据、关闭文件；不会自动停止转台运动。

## 每个实验目录中的文件

- `manifest.json`：软件版本、设备/端口/量程信息、坐标约定提示、记录时间、行数和队列丢帧计数。
- `imu_raw.csv`：IMU 原始三轴整数、换算后的加速度/角速度、温度、量程、FIFO 状态、MCU tick、帧间隔和估算样本时间。
- `turntable_feedback.csv`：转台轮询线程逐次读取的内外轴位置、速率、运动模式、使能、限位及故障状态。
- `events.csv`：连接、运动指令、停车、记录开始/结束、串口变化、丢帧/队列溢出等事件。
- `step_markers.csv`：人工工况标记。

## 时间戳解释

- IMU 的原始帧以主机接收时刻和单调时钟为基准；同一帧内 16 个样本的时间由帧间隔估算，字段明确标为 `*_est`。这不是硬件级同步时间。
- 转台反馈使用现有轮询线程完成一次缓存更新时的主机时间戳，并保留更新计数。
- 两类设备当前没有实现硬件触发同步。后续精密动态标定需要评估通讯延迟、时钟偏差和插值误差；不能把估算时间戳当成无误差的同步参考。

## 重要限制

1. 本版本没有自动执行多姿态/多速率工况，也没有自动计算陀螺仪/加速度计内参矩阵。
2. 转台反馈是 DLL 读取值，当前工程不包含对实际角速度计量精度的自动验证。标定结果的精度上限仍需依据厂家资料、校准证书和独立验证数据确定。
3. 运动前必须人工确认机械安装、线缆和旋转范围；异常时使用转台硬件急停。软件状态检查不能替代硬件安全链路。
4. 连接 2TD600 的逻辑复用现有工程。第一次运行请先在低速、无人靠近转台的条件下检查端口、运动方向、停止行为和状态反馈。
5. 原有“倾角仪校准 → 数据记录”页也可独立记录普通 IMU CSV。为了避免重复/混淆，本页开始实验记录时会要求先停止原有 CSV 记录。

## 本次静态检查

本次已对新增/修改的 Python 文件运行语法编译检查，并解析 `ui/mainWindow.ui` 的 XML 结构。当前执行环境不包含 PySide6、pyserial 运行依赖和 Windows 转台 DLL，因此没有进行真实 GUI 启动、串口通讯或转台实机联调。请在原 Windows 环境中按上述步骤验证。
