# 本次修复：ShaderBuild 异常退出与缺少 LiquidGlass.ps

## 你遇到的编译错误

- `dotnet run ... tools\ShaderBuild\ShaderBuild.csproj` 退出 `-532462766`，即 .NET 未处理异常 `0xE0434352`。该值不足以说明是 HLSL 语法、系统 DLL 还是工具进程内部异常。
- 随之 `Effects\LiquidGlass.ps` 缺失：这是上一个错误的结果，不是两个独立的错误。
- `TurntableControlView._closing` 从未被赋值：这是单独的字段警告，已移除未使用字段，采集、转台运动方法没有变动。

## 根本性调整（不再需要编译期生成 Shader 文件）

1. `DynamicInclinometer.App.csproj` 已移除 `CompileLiquidGlassShader` 的 MSBuild Exec，不再嵌套 `dotnet run` 调用辅助工程。
2. 已移除对不存在的 `Effects\LiquidGlass.ps` 的 `Resource Include`，改为嵌入 `Effects/LiquidGlass.hlsl` 源文件。
3. `Effects/RuntimeShaderCompiler.cs` 在 Windows 上通过 `D3DCompile` 在内存中尝试编译 D3D9 `ps_3_0`。
4. `Effects/LiquidGlassEffect.cs` 从 `MemoryStream` 设置 `PixelShader`，不再从磁盘或 pack URI 加载 `.ps`。
5. 如果 GPU 编译失败或硬件不支持，`LiquidGlassPane` 自动退回普通玻璃。上位机窗口仍应可以打开，具体原因在日志中显示。
6. Windows 构建校验脚本现在只检查 EXE 和 HLSL 源码，不错误地要求生成 `.ps` 文件。

## 本次没有做的事

## 在 Windows 验证

1. 解压到新目录，不要覆盖之前能启动的版本。
2. 打开 `DynamicInclinometer.slnx`，设 `DynamicInclinometer.App` 为启动项目。
3. 重新生成 Debug 版本，确认 0 错误。
4. 运行 `Windows_只编译验证_不启动转台.ps1` 可独立核查项目生成，不会启动转台。
5. 启动软件（未连接设备即可）。如果 GPU 不支持，界面应该退回普通玻璃，并写出具体异常，而不是让构建失败。
