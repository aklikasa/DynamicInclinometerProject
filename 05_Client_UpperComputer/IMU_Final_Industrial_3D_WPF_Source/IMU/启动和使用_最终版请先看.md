# 动态倾角仪 WPF 完整工程（ABS / REL 双模式）

## 交付说明
- 本文件夹为完整 C# / WPF 项目，**不是预编译 EXE**。之前版本的 ACC/GYRO 标定导入、ESKF、实时曲线、三维姿态、转台手动控制、找零和正弦运动相关代码均保留。
- 新增 ABS/REL 实时显示（Roll/Pitch/三维模型/曲线一致），REL 零点由用户明确设定；更换会话、标定文件、融合算法或重置滤波器均清除 REL 零点，防止误用历史参考。
- 自动测试和原始 CSV 继续保存**重力参考 ABS 姿态**；自动测试原有起始相对变化分析保持不变，不被 REL 显示按钮偷偷改写。
- **未在 Windows 实机编译和验证**。任何自动找零、跨周定位和双轴运动都须现场操作员确认空间与实体急停。静态检查、数学测试不能代替完整编译或硬件测试。

## 在 Windows 上构建
1. 解压 ZIP 到自己信任的本地目录，例如 `E:\IMU_Test`；不要覆盖旧版可运行工程，先备份。
2. 安装 .NET 10 Windows SDK / Visual Studio 的桌面 .NET 开发工作负载。
3. 在 PowerShell 运行 `构建和测试.ps1` 或在 Visual Studio 打开 `DynamicInclinometer.slnx`，选择 Release x64。
4. **先单独启动验证**，不要立即启动转台运动；继续检查真实 IMU、设备号、标定、时间策略和 DLL 策略事件。

## ABS / REL 两种模式如何使用
- 选择“**校准 + ESKF · 成品输出**”，载入与 IMU 设备号相同的两份 JSON 标定，连接 IMU。确认实际融合状态为 YES、新鲜数据持续到达。
- **ABS · 绝对倾角**：默认模式，不需按零点。以重力方向确定的水平参考面作为 Roll/Pitch 参考，**不是开机初始值自动清零**。安装偏差和设备标定误差仍会影响实际准确度。
- **设置当前姿态为相对零点**：在一个静止或稳定的参考位置（例如 ABS Roll 为 +10°）单击。该按钮从最新、1 秒内且已融合的四元数建立参考，切换到 REL。当传感器绕同一轴再转动约 +5°，显示对应 REL 角约 +5°。坐标轴耦合和欧拉角约定可能使非单轴运动的值不等于简单差值。
- **REL · 相对倾角**：显示相对于用户最后一次明确设定姿态的四元数旋转。没有设过零点时以 `--.---°` 显示，不假造零值。三维模型和曲线同步切换为同一参考。
- **清除相对零点**：删除参考并返回 ABS；重置滤波器、重新接入设备、换标定也会清除零点。
- Yaw 没有磁/外部航向约束，属于相对航向，**不能声称绝对真北方向正确**。
- 在 REL 显示时，`raw_processed.csv` 的 `roll_deg,pitch_deg` 仍然是**ABS 融合结果**。这是有意保留的可追溯原始分析数据，不是软件错误。
- 另外新增 `display_processed.csv`，每个样本包含界面当前 ABS/REL 模式、当前显示的 Roll/Pitch、原始 ABS、所用参考四元数及有效性标记。REL 未设零点时显示列留空，不会写入假的 0°；运行日志另记录参考操作。

## 启动时 DLL 拦截 `0x800711C7`
Windows 如提示阻止 `DynamicInclinometer.Devices.dll`，属于 DLL 运行时策略拦截；即使 C# 编译成功也无法加载。**此完整源码包不保证修复企业 App Control / Smart App Control 策略**；切勿随意关闭安全功能。优先保留旧版原样，检查该 DLL 的 Windows CodeIntegrity 事件与 ZIP 来源标记，并由系统管理员授权后再运行。

## 自动转台测试特别注意
- 不要仅因为屏幕显示 360.000° 就假设厂家绝对位置指令会选择哪条机械路径。0°/360° 的数学等价不代表转台运动方向确定。
- 转台说明书对安装姿态和双轴动作有限制；工装线缆、活动区域、实体急停和设备原生状态标志必须现场检查。
- 未经真实运动方向试验，不宣称自动找零、双轴联合运动、报告精度或停机逻辑已通过实机验收。
