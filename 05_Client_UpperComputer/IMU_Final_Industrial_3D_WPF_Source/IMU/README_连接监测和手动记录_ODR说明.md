# Precision Glass：连接监测与手动采集记录分离

## 本次客户界面修改

- **删除**实时监测首页整块“GPU 液态玻璃 / Liquid Glass / 折射强度”卡片，释放顶部布局空间。特效继续运行；调节开关与强度移到“高级参数”折叠区，不影响观测和设备数据。
- **连接设备**：沿用真实 COM/Modbus、标定和 ESKF 流程。连接后传感器持续给上位机发送数据，数字、曲线、三维模型立即更新。此时**不创建新的 CSV**。
- **开始采集**：仅在连接且有最近1.5秒内有效样本时，创建一个新的 `RUN_...` 记录目录，保存 `raw_processed.csv`、`display_processed.csv`、两个标定快照、`manifest.json`。ESKF 保持连续运行，不重置姿态零点；只记录按钮按下之后的样本。
- **停止采集**：同一个按钮切换为“停止采集”，按下后关闭并刷新记录文件，显示上次记录目录；**连接保持、实时姿态和曲线仍继续更新**。可再次开始另一段采集，新建目录。
- **断开设备**：再次点击连接按钮；若在记录，会在数据队列处理完成后先保存文件再关闭实时流。
- **数据记录**导航：只打开用户记录根目录，不触发采集。

## 什么是此时的 ODR？

上位机目前能够直接测量的是每秒**接收/处理**多少有效样本，因此新界面显示最近约1秒的**实测处理率**（单位样本/s）。它**不等同于 ASM330LHHX 芯片内部 ODR**，因为 MCU 可能分频、丢弃样本或批量发送。

硬件工程师报告芯片 ODR 为 **833 Hz**；芯片寄存器未通过此上位机读回。软件目前还保持原有候选 `200 Hz` 的 FIFO 时标重建设置（高级参数），**这只是未经固件验证的时间假设，绝不能作为硬件 ODR**。界面会分别显示“硬件报告833Hz / 目前时标候选200Hz”和“实测处理率”，避免把当前约200Hz当成833Hz。后续需由固件验证 CTRL1_XL / CTRL2_G / FIFO 和 MCU tick 后再修改。

## 已做检查 / 尚未做检查

- 源码静态：XAML 可解析、XAML 事件、按钮真实连接记录方法、独立记录器的并发互斥、原三维模型/转台控制/ABS-REL 保留、ZIP 完整性。
- **没有**在 Linux 沙盒中执行 Windows WPF 编译、真实 IMU 接收或转台硬件实验；必须在实际 Windows 环境运行 `dotnet build` 并验收。编译失败时应优先发第一条构建错误。

## Windows 快速功能验收

1. 运行新版后，保持转台断开，导入正确校准，选择 IMU COM。
2. 点击连接设备，检查 ABS/REL、三维姿态、曲线是否实时变化；确认记录目录**没有因为连接而新建 RUN**。
3. 点击开始采集，等待5秒，点击停止采集；检查两个 CSV 及 `manifest.json`，期间姿态读数仍在继续。
4. 再次点击开始采集应得到新的 RUN 目录；点击断开设备应安全结束当前记录。
5. 检查“实测处理率”是否约200Hz或接近硬件报告833Hz；无论哪个值，都需进一步用芯片寄存器和 MCU 时标核实。
