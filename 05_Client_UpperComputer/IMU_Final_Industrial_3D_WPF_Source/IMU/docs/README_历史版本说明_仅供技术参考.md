# Dynamic Inclinometer · 实时姿态融合 + 2TD-600 自动测试

本工程是 Windows / WPF / .NET 10 源码。**非已编译 EXE，也非经过真机验证的计量产品**。

## 你现在可以在工程中看到什么

1. **实时姿态输出**：导入对应设备编号的 ACC、GYRO 标定 JSON；连接真实 IMU（Modbus RTU 1,500,000 baud / slave=1 / 1000×104）；输出已标定 + ESKF 的 Roll、Pitch、三维姿态四元数、实时曲线。相对 Yaw 不具备绝对航向参考，不能被当作绝对航向。
2. **MCU tick 异常的研究级后备时间基**：不再每个成功 Modbus 帧都将连续错误计数清零后无限提示 (1/3)；若 Tick 与主机单调时间严重矛盾，明确记录原始 tick 和差值，并使用主机时标进行批次重建。保留 `TimingVerified=false`。此时可观察研究级 ESKF 姿态，不得声称计量精度达标。
3. **转台手动控制（本次纠错）**：2TD600.dll 联机读取内轴0和外轴2的**绝对角位置**、速率、使能、找零状态，以及锁紧/限位/驱动故障；每轴手动支持**相对增量**（默认）和**绝对定位**，输入速度范围0.01～60°/s（厂家硬件额定上限）；双轴可独立运动，或在现场确认允许的安装工况下使用厂家 `SetUniteAxisAction` 联合启动。恢复了内轴回零、外轴回零、双轴回零及双轴使能检测。
4. **自动正弦测试（真实命令代码已接入）**：检查双轴状态、`GetAxisFindZero`；尚未找零的轴调用原厂 `SetAxisFindZero(int,double,double)`；确认完成和零速；受控定位到外轴0°与内轴0°(Roll)或90°(Pitch)；再调用 `SetAxisSway(int,double,double)`。所有命令都对照原 Python ctypes 驱动和同版 DLL 导出。指令接受只是第一步，连续硬件反馈及安全停车必不可少。
5. **报告**：真实编码器回读和真实 ESKF 输出分别保存 CSV，生成有两条姿态曲线、误差曲线及研究性统计量的 HTML。主机时间戳尚未独立校准、坐标符号未实测确认，故不自动签发合格结论。另有纯仿真演示，明显区分真实数据。

## 使用前先读

- 必须先在安全场地确认安装工装、机械限位/实体急停、双轴坐标、运动路径、找零原点。请遵照《2TD-600 双轴转台使用维护说明书》的人员隔离要求，运行期间距旋转范围**至少 3 m**。安全确认窗口不会解除硬件急停要求。
- 如果现场无法确认找零全过程的轨迹，**不要同意执行自动找零**。找零可能产生大角度实际运动。每次自动测试前都必须重新由操作员授权现场路径。
- 轴锁定、轴故障/限位、另一轴意外运动、移动超时、IMU 数据断流、用户停止或连续反馈不一致都会导致停止请求；**软件停止不能替代独立实体急停**。
- 手动定位速度可在0.01～60°/s之间输入，但最大标称速率不是推荐值；大位移或 >10°/s 的命令要求再次确认现场路径。**自动测试预定位仍采用低速分段控制**，其运动路径/0°与360°对应关系需实机核验。
- 自动测试使能以转台 `GetAxisEnable` 真实反馈为依据，**已有使能则不重复下发**，不再要求用户先在手动页点击一次使能。每轮真实运动仍需现场安全确认。
- 说明书对特定装配状态有“一轴运动、另一轴静止”的限制；双轴联合运行不能在未知机械路径的情况下盲目使用。
- 在 0/90° 模式下通过外轴摇摆得到 Roll/Pitch 的假设需要对实际 IMU 安装轴向逐一验证。报告中的图表仅用于研发观察；SST810 报告是风格/试验工况参照，并非设备标定证书。
- 示例 ACC/GYRO 标定 JSON 的状态是 `PILOT_PASS_NOT_RELEASED`；软件没有擅自改为量产合格。

## Windows 构建 / 一键发布

安装 .NET 10 SDK、在 Windows 上执行：

```powershell
.\构建和测试.ps1
.\一键发布_Windows.ps1
```

发布结果在 `dist/win-x64/`，含转台 DLL。可以在 Visual Studio 打开 `DynamicInclinometer.slnx` 直接调试。

**重要：** 本工程在没有 Windows / .NET SDK / 真正 2TD-600、IMU 的环境中编辑和打包，只做了静态检验。不能把“代码已接入”理解成“已经现场测过实物、可以无检查投入自动运行”。详见 `docs/20261027_2TD600自动测试技术与风险说明.md`。
