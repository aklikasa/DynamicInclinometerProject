# 2TD-600 自动归零：179.87° 定位被拦截的原因与修复

## 根因

旧版本 `TurntableControlView.PositionForTestAsync()` 固定限制 `delta>90.1°`，
而当前现场反馈轴0=179.87°；机械找零标志已成立时，程序跳过机械找零，进入回零位置运动，
被这个软件上限拦截。不是硬件找零失败。原提示“可能跨0/360°”对179.87°→0°不准确。

## 基于旧标定上位机的流程

- `GetAxisFindZero` 为机械参考标志，不能代表轴当前位于0°。
- 缺机械参考时调用 `SetAxisFindZero`，等待已找零且停稳。
- 无论机械参考已经建立与否，独立核对实际角位置；非零则用 `SetAxisPosition` 定位到零度等效姿态，等待回读验证。
- 对 359.9° 使用旧标定工程确认的 0°/360° 周期等价，不盲目绕一整圈。

## 本次更改

- 状态栏明确区分“机械已找零”和“位置在零度”。
- 原来 >90° 就失败的自动定位，改为只有**额外现场路径授权**才允许执行，分段≤20°、1°/s，每段均需连续3次：位置误差≤0.05°、速度≤0.05°/s、厂家到位标志有效。
- 长行程显示完整路线和运动距离。未确认时**不发送位置命令**。
- 运行中检查方向、实际行程、另一轴静止、机械找零状态、使能/故障/限位。任一异常请求双轴停车；硬件急停仍必须独立可用。
- 内轴自动运动必须先确认外轴接近0°；当内轴非零且外轴需要移动时拒绝盲目运动，避免违反U-T设备安装运动约束。
- 0°/360° 等效位置用于最终到位核验及后续摇摆的内轴预检。
- 在现有烟雾测试中增加了 179.87°、359.87°、250°、18°及跨周边界的无硬件路径回归。

## 必须强调

代码为未实机验收的 WPF 源码。**代码可规划路径，不意味着已验证实际电机走向和机械空间**。厂商DLL位置模式的实际运动方向、回零状态、限位、物理急停、负载空间必须在现场验证，首次应用长行程须有人值守。不可通过修改阈值替代这些措施。
