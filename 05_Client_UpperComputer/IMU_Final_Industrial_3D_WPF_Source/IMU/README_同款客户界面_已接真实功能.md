# Precision Glass 同款客户界面 · 实际 WPF 实装版

本工程不是效果图或套壳网页，而是基于此前的 `IMU_PrecisionGlass_Customer_UI_Full_Source.zip` 真正修改的 Windows WPF 源代码，保留 HLSL PixelShader 的背景采样与折射、真实采集、ESKF、ABS/REL、CSV 记录、3D 姿态及 2TD-600 手动控制。

## 和用户选定参考图的对应关系

- 左侧固定导航：**实时监测、转台控制、数据记录、标定与设置**。导航按钮已绑定真实处理器；记录按钮打开采集目录。
- 顶部设备栏：真实设备号、IMU COM 口、刷新、连接/断开设备；连接后可实时查看姿态但**不开始记录文件**，连接状态来自实际数据。波特率等工程参数在高级面板中，默认 1500000，不会照搬示意图错误的 115200（后者是转台默认波特率）。
- 顶部采集记录卡：一个按钮切换“开始采集/停止采集”，只控制 CSV 记录，不断开持续运行的 IMU；显示本次记录时长、已记录样本、已知队列溢出计数及**约1秒窗口实测处理率**（不是固件标称 ODR，也不是现场验收结论）。
- GPU 卡已从首页删除；原生 WPF `LiquidGlassPane` + HLSL `ps_3_0` 动态折射及高光保留，切换与折射强度放在高级参数中；背景只是高度模糊的装饰图，不含可辨识的假角度、假设备状态。
- 中部左侧：Roll / Pitch / 相对 Yaw 数字条与真实四元数旋转的 WPF `Viewport3D`，ABS/REL 模式切换及手动参考零点按钮；绝不以 6 轴数据冒充绝对真北航向。
- 中部右侧：采样数据驱动的 Roll/Pitch `Polyline` 趋势；暂停画面不暂停原始采集，清空曲线不删除任何 CSV 记录。
- 底部左侧：ACC 和 GYRO 标定文件导入、ESKF 运行切换、实际配置/诊断及其详细设置入口。**此处不是重新进行内参实验标定**，而是导入既有标定文件。
- 底部右侧：真实转台的轴 0（内轴）/ 轴 2（外轴）绝对编码器反馈、手动相对/绝对运动输入及速度、两轴机械归零和软件停车，快捷按钮调用 `TurntableControlView` **同一套实际驱动与安全确认方法**；未连接时拒绝运动并导航到转台连接页。此处没有用固定数值假装已连接。真正的实体急停始终由硬件提供。
- 底部日志：可读、可复制、可打开保存目录；故障信息仍保留原有自动展开机制。
- **自动测试页面没有恢复**；旧辅助类文件保留但未提供运行入口。

## Windows 上如何构建

1. 原先能工作的工程必须先备份；把这个 ZIP 解压到**全新文件夹**，不要混合旧 `bin/obj/.vs`。
2. 在 Windows / Visual Studio（.NET 10 桌面开发工作负载）打开 `DynamicInclinometer.slnx`，右键 `DynamicInclinometer.App` 设为启动项目。
3. 先运行 `Windows_只编译验证_不启动转台.ps1` 或直接“重新生成”，检查 `src/DynamicInclinometer.App/bin/Debug/net10.0-windows/DynamicInclinometer.App.exe` 是否实际存在。
4. 首次启动请先在**不连接任何转台**时确认页面布局、GPU 开关、日志、ABS/REL 和曲线清空不会崩溃。再使用正确的设备号/标定，验证 IMU 串口；最后才考虑真实转台运动。
5. 在转台控制页连接本机转台对应 COM 口，实际连接后首页才会出现真实转台角度。首页“执行轴/归零”会触发安全确认，**不应直接把未知路径设为 180° 运动**。
6. DPI 100/125/150% 与分辨率 1600×900、1920×1080、1366×768 均需在 Windows 现场确认。低分辨率允许竖向滚动，不能用假缩放牺牲数字可读性。
